# 账户称号

称号归属与佩戴选择由认证服务保存，启动器与游戏内共用一份状态。支持保留的原游戏称号及社区自定义称号，不引入规则编辑器。

| ID | 称号 | 固定获取方式 |
| --- | --- | --- |
| `1007` | 首测元老 | 管理员授予 |
| `1008` | 内测精英 | 北京时间 2026 年 10 月内，功能上线后成功登录并上线 |
| `1000000` | 重燃共建者 | 代码、文档、测试、美术等有效贡献，经维护者确认后手动授予 |

自定义称号 ID 从 `1000000` 起由服务端分配，不占用原游戏 ID；新增称号统一由管理员授予，永久有效，不增加战斗属性。目录最多 64 条（包括已停用称号）。迁移只初始化“重燃共建者”的定义，不自动授予任何账户。

登录奖励窗口为北京时间 `[2026-10-01 00:00, 2026-11-01 00:00)`，服务端按数据库时间判定。仅新的成功上线请求触发发放；迁移、历史登录记录、恢复凭证、读取称号和心跳均不补发。

## 使用入口

- **启动器**：右上角账户菜单 → 我的称号。查看介绍、获取方式和持有状态，佩戴或卸下称号。
- **游戏内**：沿用原客户端个人信息中的称号入口与佩戴操作。选择经启动器向认证服务提交，成功后才更新游戏状态。
- **管理后台**：称号管理 → 新增称号，维护名称、介绍、排序与展示开关；每个称号的“发放与撤销”按登录名前缀查找账户，显示持有、佩戴及撤销状态，逐个授予或撤销。账户详情 → 称号管理入口继续保留。创建、编辑、授予和撤销均写入操作日志。

所有称号均永久有效，同一账户同一称号仅保留一条持有记录。新授予且当前未佩戴时自动佩戴；重复登录、重复授予不会改变玩家已保存的选择。

撤销保留记录并卸下该称号，之后登录不自动重新授予，管理员可以显式再次授予。关闭展示不撤销持有权，但会卸下并禁止佩戴；重新开放不自动戴回。停用称号仍可授予，开放展示后才可佩戴。目录不提供物理删除，保留历史荣誉记录。

## 同步与文案

上线后和每次成功心跳后读取称号，正常网络下约每 15 秒同步。离线、会话失效、被其他连接接管时启动器和游戏内隐藏账户称号；重新上线后从服务端恢复。请求失败不乐观修改佩戴状态，旧账户或旧在线连接的响应不覆盖当前状态。

名称最多 31 个 GBK 字节（约 15 个汉字），介绍最多 64 个 GBK 字节（约 32 个汉字）；两者使用纯文本，不接受 HTML、控制字符或 GBK 未收录的字符。原游戏称号名称、所有 ID、获取规则及登录奖励时间窗口不开放编辑。游戏内介绍追加固定获取规则，在 128 字节说明字段内以 GBK 展示。

游戏内使用原有 `USER_INFO`（命令 `31`）协议：基础信息、统计信息中的称号列表和当前称号，以及佩戴请求／响应。帧线程在进程内构造保留全部原记录的扩展目录，追加属性全零的自定义记录，再调用原客户端索引重建及界面刷新函数。原表的分配指针和数量在调用后恢复，原始名称及资源释放逻辑保持不变；目录就绪后才同步账户持有与佩戴状态。不改写、复制或分发客户端资源文件；原始函数签名不匹配时停止适配。

启动器传给 NativeBridge 的称号数据为小端格式：`uint32 version=1`、`uint32 count`，随后每条为 `int32 id`、32 字节 GBK 名称、128 字节 GBK 说明；字符串以零结尾并补零，记录按 ID 升序。空账户快照使用零长度目录数据，只清除持有与佩戴状态。

## 部署

1. 通过服务端现有 `--migrate` 流程执行至 `V007__custom_titles.sql`。`V006` 新增目录、持有记录和佩戴选择表，`V007` 新增共建者称号定义；迁移不发放奖励。
2. 配套部署服务端、启动器、NativeBridge 和 Business。C ABI 1 结构布局及导出名称保持，但目录载荷已从固定两条说明升级为上述带版本结构；组件须整包升级。旧启动器不支持自定义称号，完成升级后再向玩家授予自定义称号。
3. 在后台核对文案与展示开关。自动奖励从新版本服务处理的成功上线请求开始，不扫描旧记录。

接口为 `GET /api/v1/auth/online/{connectionId}/titles`、`PUT .../titles/equipped`，后者传入 `{"titleId":1000000}` 或 `{"titleId":null}`。均沿用 Bearer、机器绑定和在线归属校验，详见 [OpenAPI](../server/contracts/openapi-auth-v1.yaml)。旧服务缺少接口时保留本地游戏功能，不伪造称号归属。

## 专项验证

在仓库根目录执行，构建与测试要求见[开发说明](development.md)：

```powershell
mvn -f server/pom.xml '-Dtest=TitleCatalogueTest,TitleServiceTest,AdminUiTest,PresenceServiceTest,ServerIntegrationTest#title*+startupMigratesBeforeInitializingAdmin' test
python -m pytest -q tests/python/test_titles.py
python scripts/build.py --project managed
& ./artifacts/bin/T7R.ManagedHarness/x64/Release/net48/T7R.ManagedHarness.exe --title-tests ./artifacts/test-results/titles
```

原生测试工程编译后，可执行 `T7R.RuntimeTests.exe --title-tests` 验证 x86 帧线程目录扩展、原索引与刷新调用、资源所有权及寄存器保持；`--title-runtime PACKAGE_ROOT` 验证原生／Python 请求、确认、超时与账户代次隔离，`PACKAGE_ROOT` 使用包含 Business 和 Python 运行时的合成测试目录。实机验收应在游戏大厅和个人信息页检查自定义名称、介绍、佩戴／卸下、后台改名、撤销／暂停展示，以及断网后恢复。
