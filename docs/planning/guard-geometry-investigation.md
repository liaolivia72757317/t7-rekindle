# 普通格挡几何来源核实

## 结论与实施状态

原始普通格挡的几何来源按武器核实，不设置全局 `20002` 默认值。`1030622`、`1030411` 的原服防御几何仍未证实。项目现采用独立于该未决结论的角色正面查询盒：攻击刀刃扫掠先接触盒体，再由服务端检查方向、阶段与性能；不再要求防守武器刀刃相交。此实现不代表原始服务器使用相同形状；尺寸与结算规则见[武器拦截、挡反与盾牌](../combat-rules.md#武器拦截挡反与盾牌)。

资源定义、附属实体创建、刚体生成、状态启用和实际接触查询是不同证据层次。附属清单没有某个 ID，不排除其他动态装配路径；反过来，资源名称、`DefenseRB` 或尺寸字段存在，也不证明普通格挡使用该资源。

本次兼容样本的清单覆盖 36 名可选先锋、120 件可选装备（含徒手）、23 个分类：

| 资源事实 | 数量／结果 | 含义 |
| --- | --- | --- |
| 可选主手的分类刚体名为 `AttackRB`、层值为 3 | 103 件 | 原始初始化的层检查跳过创建；不是防御几何映射 |
| 可选盾牌的分类刚体名为 `DefenseRB`、层值为 6 | 17 件 | 通过该层检查；仍需区分创建、激活和查询 |
| 当前可选装备及其递归附属资源 | 147 条唯一资源 | 其中没有 `20002`、`20006` |
| 分类 20 的武器防御资源 | `20002`、`20006` | 是候选，不是全武器默认值 |
| 全武器表直接附属清单引用 `20002` | 0 条 | 仅排除这条配置装配路径 |
| 全武器表直接附属清单引用 `20006` | `20014`、`20027` | 两件对照武器均不在当前可选装备集合中 |

“可选装备”由本项目的先锋／武器组解析规则确定，不等同于原表所有武器。不同分类即使层值相同，也没有据此合并普通格挡实现。

## 可重复的只读清单

在项目根目录运行；将 `CLIENT_ROOT` 替换为客户端根目录的绝对路径，输出目录需已存在：

```powershell
python scripts/inspect_guard_geometry.py `
  --client-directory "CLIENT_ROOT/Bin" `
  --include-weapon 1030622 --include-weapon 1030411 `
  --include-weapon 20014 --include-weapon 20027 `
  --output ".local/guard-geometry.json"
```

工具只读当前客户端的资源，不依赖其他工程或运行中的游戏。它拒绝覆盖输出、将输出写入客户端目录，以及已知不支持的资源覆盖布局。

输出包括：

- 当前可选武器及所属先锋；额外指定的对照武器、分类 20 候选和递归附属资源。
- 分类、主副手、实体模板、模型、挂点、刚体名、层检查结果及原始位置／旋转／尺寸参数。
- 全表对候选资源的直接引用；零占位、缺失附属资源分别保留，不静默改写。
- 相关实体模板的组件参数和行为树绑定；`Header`、`Entity` 分开记录，不猜测通配符的解析结果。

报告固定标记 `resourceFactsOnly=true`；`ordinaryGuardSource=null` 表示工具没有证明普通格挡来源，不表示原游戏没有防御能力。`layerGate=passes` 仅表示通过已核实的层检查，`sizeRaw` 不预先解释为全尺寸或半尺寸。报告含用户自行准备的资源信息，应留在本地，不作为随项目分发的资源包。

布局核对点如下，偏移均相对表行：

| 表 | 行宽 | 字段 |
| --- | --- | --- |
| `s_weapon_cli.bin` | 2829 | 分类 `+0x38`；实体模板 `+330`；模型 `+390`；挂点 `+930` |
| 同上 | 2829 | 附属数量 `+0x3E2`，最多 5 个 ID 从 `+0x3E4` 开始；位置／旋转／尺寸 `+0x3F8/+0x404/+0x410` |
| `s_weapon_category_cli.bin` | 550 | 层值 `+0x34`；刚体名 `+0x78`；刚体骨骼名 `+0xB8` |

这些字段由原始访问函数和实际消费路径交叉核对；几何参数读取成功不代表其防御用途已证实。

## 武器结论与链路证据

| 对象 | 已验证事实 | 普通格挡来源结论 |
| --- | --- | --- |
| `1030622` | 分类 4、`AttackRB`、层 3；附属 `[99006, 20004, 99002, 99008]` | 原服来源未证实；项目使用角色正面查询盒 |
| `1030411` | 分类 32、`AttackRB`、层 3；附属 `[0, 20004, 99002, 99008]` | 原服来源未证实；项目使用角色正面查询盒 |
| `20002` | 分类 20、层 4，挂点 `FXRoot`，无模型 | 候选；未建立到上述武器的选择／启用链 |
| `20006` | 分类 20、层 4，挂点 `RagSpine`；被两件对照武器引用 | 引用已证实，普通四向使用关系未证实；本期不接入骑乘 |
| 当前盾牌 | 分类 17、层 6，自身为 `DefenseRB`，使用防具实体模板 | 保留现有真实副手路径，不替换为独立代理 |

代码核对地址均为当前兼容客户端映像的 RVA：

1. **资源选择／附属装配**：`0x6418F0` 读取附属 ID，`0x63C530` 消费清单并按实体模板创建附属武器。它证明配置被消费，不证明附属几何何时作为防御体生效。
2. **刚体生成**：`0x645E70 → 0x63C1A0` 对层 3、4、7 跳过原始创建区块。正常创建路径通过 `GeHavokPhysicable +0x68` 进入 `0x3C72E0`，操作物理组件的 `+0x34` 集合。当前采集器正依赖该集合。
3. **状态传播**：`0x4899E0 → GeWeapon +0x64 → 0x63C220` 更新武器动画、行为树并通知附属武器。已查路径没有补建这两把武器的普通格挡碰撞体。
4. **额外消费者排除**：几何参数的另两处消费者属于 `GeFlyer`；`0x4A3870` 操作已有 `AttackRB` 的禁用，不创建普通防御体。`0x483240` 校验命中事件中的防御方所有者，也不选择防御资源或生成几何。
5. **校验动作与反馈**：原客户端的主动／被动格挡校验动作执行槽均落到 `0x6E1870` 的空实现。防御通知、格挡值通知和状态同步有实际客户端消费者，但不能据其消息字段补出原服务端接触算法。

实体模板补充核对：近战武器绑定了被击处理树，树中处理已有的命中事件、校验请求和反馈；虚拟武器模板声明物理／挂接组件，但没有直接给出普通格挡盒。近战、虚拟与不同盾牌模板的挂接缩放参数存在差异，不应按一个通用变换公式替换全部原始行为。

`99008` 虽有“防御”名称，实际分类刚体名仍为 `AttackRB`、层 7；`99006` 为冲刺身体资源。它们的名称和附属关系不足以作为普通四向防御来源。

既有实机采样已经观察到 `1030622` 在防御保持时主手激活、刀刃姿态可读而防御集合为空。本轮没有修改客户端内存或启动新的战局；现有 capture 只用于核对缺失证据，不外推全部武器的实际运行结果。

复核的 5 份既有 capture 均通过结构和接触水位检查；其中 4 份含战局，累计 51,868 次接触、1,999 次目标处于普通防御状态的身体接触，非零 `defenceWeaponId` 接触为 0。另一份没有战局，不计入有效格挡样本。身体接触记录中的防御武器 ID 为零，因此这些汇总不直接归因到某把装备，也不把接触次数等同于实际扣血次数。

### 未决项与停止条件

两把故障武器均缺少“普通防御资源／形状选择 → 生成或独立查询 → 状态启用”的完整证据链。当前没有足够材料区分其他动态装配路径与仅存在于原服务端的算法。

恢复调查需要新的直接证据，例如明确消费防御参数的调用点、可关联武器与状态的运行对象，或原服务端相关资料。缺少这些证据时保留未决状态，不继续以资源名称、全库关键词命中或反复观察空集合推导替代实现。

## 原始逻辑接入门槛与项目实现

按原始逻辑接入时，仍需明确来源、形状／尺寸语义、挂点变换、有效阶段和生命周期；等价重建需证明原始几何及消费语义。项目当前的主手正面盒体是自建查询，不依赖未决的原服映射，替代主手原生根形状与刀刃胶囊。盾牌保留原生根形状。接触协议 v5 显式标记盒体证据，固定 C ABI 不扩展。

以下是已接入的项目规则，不是对原始算法的还原声明：

| 来袭攻击 | 允许的普通防御姿态 | 共同前提 |
| --- | --- | --- |
| 上劈 | 上防 | 有效防御几何先形成接触 |
| 下刺 | 下防 | 同上 |
| 左横击、右横击 | 左防或右防 | 同上；上防、下防不接横击 |

普通格挡在保持与成功反馈阶段均执行上述方向过滤。挡反使用同一查询盒，限防守方 Prepare 且接触位于进攻方完整 Strike 前三分之一；方向配对不变。盒体性能破防先记录减伤，等待同一刀真正接触身体才扣血；盾牌、冲刺方向策略和格挡值规则保留。

当前接入保留同帧防御／身体／场景接触及水位顺序，保留无效防御后的身体候选；不用代理资源 ID 替代 `defenceWeaponId`。盒体接触由同一游戏线程写入既有接触日志，不在业务轮询时拼接历史防守姿态。
