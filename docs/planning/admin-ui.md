# 服务端管理 UI 规范

版本：1.0 · 日期：2026-10-15
范围：页面外壳、视觉变量、通用组件、交互状态、可访问性与静态资源组织。

## 1. 视觉基线与决策优先级

采用 **Tabler 浅色、双层顶部横向导航、居中内容容器**。整体保持常规企业后台的清晰度和信息密度，以白色面板、浅灰背景、细边框和单一蓝色主色构成界面。

本规范的尺寸、颜色、间距和行为选择是项目统一取值，不是对 Tabler 官方默认值的复述。Tabler 提供布局和通用组件基础；本项目仅做收敛性的样式覆盖，不重新实现整套组件库。[R1][R2]

实现冲突时按以下顺序处理：本规范的明确规定 → `ui-tokens.css` → 通用组件模板 → 具体页面。本文与 `server/src/main/resources/static/admin/assets/` 中的配套样式应同步修改。早期效果图仅用于理解视觉方向；其中的示例文字、字段、数据、装饰图、同时出现的浮层，不作为实现要求。

**整体约束：**不使用常驻左侧主导航，不把品牌、全部导航和工具区挤入同一行；不使用玻璃拟态、背景插画、渐变主按钮、发光描边、大面积阴影、彩色卡片墙和页面入场动画。品牌位置使用经批准的既有素材，保持原始比例，不从效果图重新描绘品牌图形。

## 2. 页面外壳

### 2.1 标准结构

```text
┌──────────────────────────────────────────────────────────┐
│ 品牌 / 平台名称                              全局工具区  │  品牌工具栏
├──────────────────────────────────────────────────────────┤
│ 一级导航    一级导航    一级导航 ▾    …                  │  横向主导航
└──────────────────────────────────────────────────────────┘
       面包屑 / 页标题                         页面操作
       ┌────────────────────────────────────────────┐
       │              页面内容                      │
       └────────────────────────────────────────────┘
       页脚辅助信息
```

顶栏和导航的白色背景横向铺满视口，但它们的内部内容、页标题、正文、页脚使用同一条左右对齐线。使用独立的 `.ui-container` 统一容器宽度；不要在某个页面单独改成全宽。

| 项目 | 统一取值 / 行为 |
| --- | --- |
| 品牌工具栏 | 最小高度 56 px；图形高度 28–32 px；文字品牌约 18 px |
| 横向主导航 | 最小高度 48 px；图标 18 px；图标与文字间距 8 px |
| 默认内容最大宽度 | 1320 px；不随超宽屏无限增大 |
| 页边留白 | 视口 ≥ 768 px 时每侧至少 24 px；更窄时 16 px |
| 页面内容顶部间距 | 24 px；窄屏 16 px |
| 标题区到内容 | 24 px |
| 并列面板间距 | 16 px |
| 主要纵向区块间距 | 24 px |
| 顶部行为 | 两层顶栏作为整体吸顶；不让两行分别覆盖正文 |
| 页面滚动 | 正文使用页面纵向滚动；不在每个卡片里建立纵向滚动条 |
| 页脚 | 普通文档流；不是固定悬浮条 |

上述高度为最小高度，不允许为了固定截图高度而截断文字。窗口缩放、字体缩放或导航展开后，运行时应测量顶栏实际高度并更新 `--ui-shell-height`，用于滚动定位和通知避让。

### 2.2 主导航

导航默认使用图标加文字。未选中项为次级文字色；悬停使用浅灰底；当前项使用主色文字与底部 2 px 蓝色指示线，不使用大块实心蓝色背景。只有可展开的项目显示下拉箭头。

一级导航按“首页、服务维护、玩家管理、系统管理、组件验收”排列。服务维护包含公告管理、QQ 群校验、称号管理；玩家管理包含账户与会话、操作记录；系统管理包含管理员密码、操作记录。

一级导航不自动折成两行。窄屏或横向空间不足时使用折叠导航，不将二级菜单再嵌套进“更多”。分组通过按钮展开一层子菜单，当前页所属分组保持选中，子链接使用 `aria-current="page"`；导航区域设置可区分的名称。[R2]

全局工具区保持稳定顺序、稳定占位；只有图标的按钮必须有可访问名称及悬停提示。工具区缩窄时可以隐藏辅助说明，但不能把可操作控件裁掉。

### 2.3 页面标题与局部导航

每页一个主标题 `h1`。标题可搭配一行说明；没有必要的说明不填占位文案。面包屑使用 12 px 次级文字，末级不再重复做可点击链接。

文案不重复标题、按钮含义或使用者已知的操作流程；保留输入限制、操作后果和故障处理提示。时间通过共享 `time` 模板与 `Intl.DateTimeFormat` 按浏览器时区及语言区域显示，不逐字段标注 UTC，不修改存储或接口时间。日期包含年月日，时间精确到秒；空值保留原状态，异常值显示“—”，禁用 JavaScript 时显示带时区的 ISO 原值。

内容页面统一显示“首页 / 所属分组 / 当前页”，详情页补充可返回的列表入口。面包屑使用具名导航及有序列表，末级标记 `aria-current="page"`；分组尚无独立页面时使用纯文本，不生成无效链接。玩家操作记录与系统操作记录暂显示“建设中”，保留各自菜单选中态和面包屑，不加载或分类审计数据；原 `/admin/audit` 继续提供已有全部记录。

页面级操作右对齐，主操作放最右；空间不足时移动到标题下方独立成行。标签页用于同一对象或同一任务范围内的内容切换，不能替代全局主导航。

## 3. 设计变量

### 3.1 色彩

| 语义 | 变量 | 色值 |
| --- | --- | --- |
| 页面背景 | `--ui-bg` | `#F5F7FA` |
| 内容表面 | `--ui-surface` | `#FFFFFF` |
| 次级表面 / 表头 | `--ui-surface-muted` | `#F8FAFC` |
| 主要文字 | `--ui-text` | `#182433` |
| 次级文字 | `--ui-text-secondary` | `#5B6778` |
| 辅助文字 | `--ui-text-muted` | `#667382` |
| 面板 / 分隔边框 | `--ui-border` | `#DEE3EA` |
| 可操作控件边框 | `--ui-control-border` | `#8793A3` |
| 主色 | `--ui-primary` | `#206BC4` |
| 主色悬停 | `--ui-primary-hover` | `#1B5AA5` |
| 主色按下 | `--ui-primary-active` | `#164C8E` |
| 主色浅背景 | `--ui-primary-soft` | `#E9F1FB` |
| 成功 / 成功浅背景 | `--ui-success` / `--ui-success-soft` | `#2B7D35` / `#EAF5ED` |
| 警告 / 警告浅背景 | `--ui-warning` / `--ui-warning-soft` | `#A35D0A` / `#FFF4DD` |
| 危险 / 危险浅背景 | `--ui-danger` / `--ui-danger-soft` | `#C43131` / `#FCEDED` |
| 中性状态 / 中性浅背景 | `--ui-neutral` / `--ui-neutral-soft` | `#5B6778` / `#EEF1F5` |

信息类状态复用主色，不增加另一套蓝色。不同分类默认使用中性标签，不给每一类分配一种彩虹色。成功、警告、危险仅表达语义，不作为普通分类装饰。

面板分隔线可以较淡；输入框等用于辨认操作区域的边界使用更清晰的控件边框。不要为了“更轻”把辅助说明、错误文字或输入框轮廓降到难以辨认。

### 3.2 字体、数字与排版

字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。使用本机字体，不依赖在线字体加载。

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页标题 | 24 / 32 px | 600 |
| 弹窗标题 | 18 / 26 px | 600 |
| 卡片 / 区块标题 | 16 / 24 px | 600 |
| 正文、输入、按钮、导航 | 14 / 20 px | 400–500 |
| 辅助说明、表头、标签 | 12 / 18 px | 400–500 |
| 关键数值 | 28 / 36 px | 600 |

除徽标极短计数外，不使用小于 12 px 的可见文字。正文不要依靠连续加粗制造层级。表格数值采用等宽数字 `font-variant-numeric: tabular-nums`；等宽字体仅用于确有必要的技术文本，不用于整页正文。

### 3.3 间距、边框与圆角

间距只使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 px`。按钮与图标间距 8 px；标签到控件 8 px；控件到帮助文字 4 px；表单项纵向间距 16 px；表单分组之间 24 px。

控件圆角 4 px；卡片、下拉菜单、模态框圆角 6 px。头像和小型状态胶囊允许全圆角；普通按钮、输入框、面板不胶囊化。

边框统一 1 px。普通卡片无阴影；下拉菜单、浮动通知使用轻阴影；模态框可使用稍强阴影。组件不能同时叠加粗边框、重阴影和发光效果。

## 4. 图标与通用操作

图标统一使用 **Tabler Icons 的线性 SVG**。图形按 24×24 画布、统一笔画粗细组织，常规显示尺寸为 16 / 18 / 20 / 24 px；同一个位置不混用不同尺寸或不同套系。[R10]

导航图标 18 px，按钮图标 16 px，输入附属图标 18 px，提示图标 20 px。装饰性 SVG 设置 `aria-hidden="true"`；无可见文字的操作按钮设置准确的 `aria-label`。图标颜色默认继承文字颜色。

桌面图标按钮点击区域至少 32×32 px，触摸环境至少 44×44 px；可见图形大小不等于点击区域大小。本项目采用比 WCAG 2.2 最小目标尺寸条款更宽裕的默认操作区，不将此视为整页已满足全部无障碍要求。[R8]

### 4.1 按钮

| 类型 | 视觉 | 使用方式 |
| --- | --- | --- |
| 主按钮 | 蓝底白字 | 同一操作区最多一个 |
| 次按钮 | 白底、可辨边框、深色文字 | 取消、返回及普通辅助操作 |
| 文字按钮 | 主色文字、透明底 | 低强调的轻操作 |
| 危险操作 | 优先红色文字或描边 | 确认区域的最终危险动作可用红色实底 |

默认高度 36 px，小按钮 32 px，大按钮 40 px。宽度随文字自适应，左右内边距 12 px；普通弹窗底部按钮最小宽度 80 px，不强迫所有按钮等宽。

必须定义默认、悬停、按下、键盘聚焦、禁用和加载状态。加载时保留按钮宽度，显示小型加载指示与进行中文案，阻止重复提交。禁用时不得保留悬停效果；需要解释原因时把说明放在可聚焦的相邻帮助入口，不依赖禁用按钮本身触发 Tooltip。

只有完成状态已被确认后才显示成功反馈，不能点击即显示成功。确认动作文案使用明确动词，避免所有弹窗都只写“确定”。

## 5. 面板、列表与表格

### 5.1 面板

白色背景、1 px 面板边框、6 px 圆角；卡片标题区和常规内容区使用 16 px 内边距，复杂表单正文可使用 24 px。优先以分组标题、间距和分隔线组织内容，不连续套三层卡片。

列表结构统一为：**标题区 → 筛选区 → 操作工具栏 → 表格 → 分页**。筛选区与表格可以位于相邻卡片中；工具栏和分页应贴近表格，不各自再包装一张无意义的卡片。

### 5.2 筛选区

默认呈现一行常用筛选项，超过当前布局容纳数量的项目进入“更多筛选”。筛选字段上方放标签，不用占位文字取代标签；同一行控件底部对齐。

“查询”作为明确提交入口；“重置”恢复默认筛选状态并执行一次查询，回到第一页。筛选改变后不悄悄保留不适用的页码。已生效筛选与尚未提交输入应可区分。

### 5.3 表格

| 项目 | 规定 |
| --- | --- |
| 表头 | 浅灰底；12 px / 500；常规高度 40 px |
| 数据行 | 默认最小视觉高度 44 px；双行内容自然增高 |
| 单元格间距 | 水平 12 px、垂直 6 px；按内容允许增高 |
| 分隔方式 | 默认横向浅分隔线，不默认画满纵向网格 |
| 对齐 | 文本左对齐，数值右对齐，复选框和图标操作居中 |
| 悬停 | 浅灰背景，不改变行高、不出现重阴影 |
| 选中 | 浅蓝背景，同时有勾选标记；不能只有颜色 |
| 长文本 | 指定列可省略；必须提供完整内容入口 |
| 操作列 | 常见动作最多两个，其他进入“更多”；不把多个图标紧密挤在一起 |
| 宽表格 | 只在表格区域横向滚动；操作列可按统一模板固定 |

使用真实 `<table>`、`<thead>`、`<th>` 等语义。可排序列采用明确的排序按钮，显示方向，并设置相应的 `aria-sort`。默认三态为未排序、升序、降序；无排序能力的表头不能显示排序图标。

多选的“全选”默认仅作用于当前页；跨页选择必须有显式入口和明确的数量说明。批量操作区只在存在选中项时显示，给出选中数量与取消选择入口。表格行默认不整体可点击，避免与内部复选框、链接和菜单冲突。

分页只保留一处，放在表格底部：左侧显示总量/当前范围，右侧显示每页数量和页码。更改页大小回到第一页。返回列表时恢复用户原有的筛选、排序和滚动位置；异步响应不得用较旧结果覆盖较新结果。

### 5.4 普通列表和标签

文本列表行使用一致的主次文字结构；行末放时间、状态或轻操作。状态标签高度约 22 px，12 px 文字，默认浅色底和同色深文字。数字徽标与状态标签分开，不用大胶囊承载整段说明。

状态必须能通过文字、图标或形状辨识，颜色只是辅助。空缺信息使用统一占位“—”，不能显示 `null`、`undefined` 或失效图片。

## 6. 表单

表单标签置于控件上方，14 px / 500，标签与输入间距 8 px。默认控件高度 36 px，使用实际关联的 `label`；必填标记紧跟标签，标签宽度和对齐方式在同一表单内一致。

双列表单只用于足够宽的内容区域；每列宽度不足约 280 px 时自动切为单列。长文本、连续说明、复杂选择器和多行输入占满一行。相关字段使用有名称的分组，而不是只靠颜色分组。

占位文字仅示意输入格式，不能替代字段名称、默认值或错误信息。只读字段仍应允许查看和复制；禁用字段说明不可操作原因。文本域最小高度 96 px，允许按内容增长，必要时允许纵向调整。

### 6.1 校验与状态

初始未操作状态不显示红色错误。首次提交时校验全部字段；用户已操作的字段可在失焦时校验，报错后可随修改重新校验。不要在用户尚未完成输入时不断打断。

错误信息紧邻控件下方，使用危险色、错误标记和一句可执行的说明，并通过 `aria-describedby` 关联；无效控件设置 `aria-invalid="true"`。Tabler 的 `.is-invalid` / `.is-valid` 可作为视觉状态基础，但是否显示成功态由本规范控制：一般不为每个正确字段添加绿色勾选。[R3]

提交失败保留输入；焦点移动至错误摘要或第一个错误字段。长表单可在顶部给出错误摘要，但不能只显示顶部 Toast 而不指出出错位置。提交过程中保留表单位置，不整页闪白。

### 6.2 单选、复选、开关与选择器

单选表达互斥选择；复选表达独立选择；开关仅表达明确的开/关状态。标签整体可点击，并保留原生键盘交互。表单内开关默认只改变待提交值，随表单统一保存；独立即时控件必须明确体现即时生效，并提供加载/失败恢复反馈。

简单选择优先使用原生选择器；需要检索或多选时使用统一增强组件，不能在不同页面引入多个外观和键盘行为不同的选择库。输入附属的清空、显示/隐藏、复制按钮都必须可聚焦并有名称。

### 6.3 表单底部操作

短表单在内容底部放操作区；长表单允许使用内容范围内的吸底操作栏。右侧依次放取消/返回、主提交；不并列显示两个同权重的实心主按钮。吸底栏必须预留内容空间，不能遮挡最后一个字段或键盘焦点。

存在未保存修改时，离开页面或关闭容器需要提示。若表单已在模态容器内，离开确认在当前容器内切换呈现，不再叠加第二个模态框。

## 7. 模态框、抽屉与浮层

### 7.1 模态框

用于短任务、简短表单和明确确认。长篇阅读或复杂多步骤操作使用独立页面，不无限扩大模态框。

| 项目 | 规定 |
| --- | --- |
| 小型 / 标准 / 大型宽度 | 440 / 640 / 880 px；均受视口宽度约束 |
| 小屏边距 | 左右至少 16 px；极窄屏可使用全屏模式 |
| 圆角 | 6 px |
| 结构 | 标题及关闭 → 内容 → 底部操作 |
| 内容内边距 | 24 px；紧凑说明弹窗可为 16 px |
| 最大高度 | 不超过视口可用高度减 48 px |
| 长内容滚动 | 仅内容区滚动，标题与操作区保持可用 |
| 遮罩 | `rgba(24, 36, 51, .36)`，不使用背景模糊 |

普通可丢弃的提示可以点击遮罩关闭；含未保存输入的表单和需要明确确认的弹窗，遮罩不直接关闭。`Esc` 按取消/关闭路径处理，有未保存内容时转为当前容器内的离开确认，不能默认执行主动作。

同一时刻只允许一个模态焦点范围。打开时焦点进入弹窗，`Tab` / `Shift+Tab` 在其中循环，关闭后恢复到触发元素或逻辑上的后续位置。危险确认的初始焦点放到安全动作，而不是危险按钮。标题和关闭按钮必须有可访问名称。[R4][R6]

**禁止把“成功通知＋尚未完成的确认弹窗＋同一动作菜单”作为同一真实状态保留。** 菜单触发弹窗后先关闭菜单；操作成功后关闭相关确认界面，再更新内容并反馈结果。

### 7.2 抽屉

默认从右侧进入，标准宽度 480 px，复杂内容使用 640 px；窄屏全宽。抽屉中保留标题、关闭按钮、内容滚动和必要的底部操作。

默认抽屉为模态型，背景不可交互，并遵循与模态框相同的焦点规则。需要旁边页面持续可操作时，应采用页面内的非模态详情栏，不伪装成模态抽屉。

抽屉内发起确认时，在当前容器内切换确认内容，或先结束抽屉的焦点管理再打开确认框，不能同时运行两个独立的焦点陷阱。

### 7.3 下拉、Tooltip 和 Popover

| 类型 | 使用范围 | 约束 |
| --- | --- | --- |
| 下拉菜单 | 同一入口的多个动作 | 最小宽度 176 px；菜单项最小高度 36 px；分组以分隔线表示 |
| Tooltip | 一句短解释 | 最大宽度约 280 px；鼠标停留约 300 ms 后显示；键盘聚焦可显示；Esc 可关闭 |
| Popover | 较长说明或轻量补充内容 | 最大宽度约 360 px；点击/键盘可开启；明确关闭方式 |

必要字段规则和错误解释不能只存在于 Tooltip。Tooltip 不放可点击按钮；含交互的内容使用具有适当焦点管理的 Popover 或独立区域。

浮层不得被表格的 `overflow` 裁切。普通页面浮层可挂载到统一浮层容器；模态框内部浮层必须留在当前模态的可访问范围内，不能为逃离裁切而破坏焦点管理。

## 8. 提示、通知与异常状态

### 8.1 反馈分工

| 形式 | 使用场景 | 生命周期 |
| --- | --- | --- |
| 字段内联反馈 | 指向具体输入问题 | 修正或状态解除前保留 |
| 区块 / 页面 Alert | 对当前内容持续有效的说明或异常 | 问题解除或用户明确关闭 |
| Toast | 非阻断的短结果反馈 | 成功默认 3 秒，普通信息 5 秒；可手动关闭 |
| 持久通知列表 | 需要稍后查看的消息集合 | 不因短时超时而消失 |
| 模态确认 | 需要明确选择才能继续 | 用户处理后关闭 |

Toast 宽度默认 360 px，右侧距视口至少 24 px，顶端避开实际顶栏；窄屏每侧留 16 px。最多同时显示 3 条，间距 8 px；同类重复消息合并计数或更新现有消息，不连续堆积。

错误、警告及包含操作入口的消息不依赖自动消失；关键内容同时保留在相关区域或持久通知中。自动消失的消息在鼠标悬停/键盘聚焦时暂停计时。Toast 不主动抢焦点。成功和普通反馈使用预先存在的 `role="status"` / `aria-live="polite"` 区域；确需立即告知的错误可使用 `role="alert"`，避免把所有消息都设为打断式播报。[R5]

通知列表使用白色面板、清晰标题、时间和未读标记；宽度约 380 px，列表最大高度约 420 px，长列表内部滚动。通知图标、未读徽标和状态颜色都不能代替可读文字。

### 8.2 必备页面状态

| 状态 | 呈现方式 |
| --- | --- |
| 首次加载 | 简单骨架或局部加载指示，预留内容尺寸 |
| 局部刷新 | 保留旧内容，标明更新中；不整页覆盖 |
| 暂无内容 | 中性图标、短标题、必要的下一步入口 |
| 无匹配结果 | 保留筛选项，提供清除筛选入口 |
| 加载失败 | 原区域内显示说明与重试，不伪装成空数据 |
| 操作失败 | 保留上下文、输入和滚动位置，解除错误的加载锁定 |
| 内容过期 / 连接中断 | 明确说明当前结果可能不是最新，不把旧内容冒充新内容 |
| 不可访问 | 清楚说明无法访问，并提供安全的返回方式 |

状态区图标约 32–40 px，不使用大型插画。加载时间超过约 300 ms 才显示明显加载指示，避免瞬间闪烁；持续较长时提供过程说明，不能无限旋转且无出路。

## 9. 通用页面模板

| 模板 | 固定结构 | 限制 |
| --- | --- | --- |
| 登录 / 入口页 | 精简品牌栏、居中入口卡片、少量辅助信息 | 卡片建议 420 px；不展示不可用的主导航和大篇产品宣传 |
| 概览页 | 标题、少量摘要卡、主要内容面板、简短动态区 | 不为了填满画面堆叠图表；关键数字不滚动播放 |
| 列表页 | 筛选、工具栏、表格、分页 | 不默认用大卡片替代表格 |
| 表单页 | 标题、分组表单、必要辅助信息、提交区 | 辅助信息不是必须的右侧大栏 |
| 详情页 | 标题、分组只读信息、必要的局部标签页 | 不把所有只读值装成禁用输入框 |

图表只在帮助理解内容时使用，保持二维、清楚坐标/单位、有限的系列颜色，提供文字摘要或数据替代。图表的空数据、加载和错误状态同样需要设计。禁止装饰性的 3D 图、发光曲线、自动切换图表和伪实时动态。

## 10. 响应式、动效与层级

### 10.1 响应式

| 视口宽度 | 布局行为 |
| --- | --- |
| ≥ 1400 px | 内容最大 1320 px，居中；支持多列面板和双列表单 |
| 992–1399 px | 内容宽度等于视口减两侧留白；主导航优先收纳低频入口 |
| 768–991 px | 导航折叠；摘要可两列；正文按宽度减少列数 |
| < 768 px | 单列优先；操作区可换行；抽屉可全屏；弹窗缩到可用宽度 |

断点是行为切换参考，不允许为了“凑齐桌面布局”不断缩小字号。检查 1366×768、1440×900、1920×1080 以及窄窗口；同时检查 200% 浏览器缩放。窄屏不得出现整个页面横向滚动，确需二维浏览的宽表格使用局部滚动。

### 10.2 动效

悬停、聚焦和颜色过渡约 120–150 ms；下拉/弹窗约 150 ms；抽屉约 180–200 ms。只做必要的状态反馈，不对每张卡片添加入场、弹跳或缩放。

尊重 `prefers-reduced-motion`：关闭非必要位移动画，加载状态仍保留可识别文字或静态提示，不能仅删除动画导致状态不可理解。

### 10.3 层级

表格固定单元格和内容吸底栏使用局部低层级；全局吸顶头部使用 1020。下拉、抽屉、模态框、提示浮层与 Toast 保留所锁定 Tabler 版本的原生层级关系。配套通知容器的基础层级为 1090。

不在具体页面写 `z-index: 99999` 解决遮挡。模态打开时，背景不可点击；较高的视觉层级不等于可以跨越当前模态的焦点范围。

## 11. 可访问性与交互底线

正文和必要辅助文字以至少 4.5:1 的对比度作为检查目标；大字号文字按 WCAG 的大文本条件至少 3:1。用于辨认控件和状态的必要非文本视觉线索按至少 3:1 检查。这里列出的条件是验收的一部分，不等于覆盖全部 WCAG 成功准则。[R7][R9]

所有功能必须能用键盘到达和操作；可见焦点使用 2 px 实色主色轮廓及 2 px 偏移，不能仅依赖很淡的阴影。焦点不得被吸顶栏、吸底栏或浮层遮挡。

动作使用 `button`，跳转使用真实链接；当前页面设置 `aria-current`，输入错误设置可访问关联，折叠按钮维护 `aria-expanded`，加载区域维护 `aria-busy`。导航、表单、弹窗及通知不能只“看起来正常”而缺失语义。

移动和缩放后的文本不得裁切。图标、颜色、悬停和动画不能成为理解内容的唯一方式。截图、自动化检查和真实键盘/读屏检查应结合，不能仅凭截图宣称完成无障碍验收。[R6][R7][R8][R9]

## 12. 前端资源与 Tabler 使用约束

Spring Boot 可从 classpath 的 `/static` 等目录提供静态内容。推荐保持同源、本地资源组织，不以运行时公共 CDN 作为界面正常显示的前提。[R11]

```text
server/src/main/resources/
  templates/
    fragments.html          # 外壳、图标、确认弹窗与通知容器
    ui-components.html      # /admin/ui-components，仅管理员可访问
    *.html                  # 各管理页面
  static/admin/assets/
    vendor/tabler/1.6.1/    # 原始 CSS / JS、source maps 与许可
    vendor/tabler-icons/3.49.0/LICENSE
    icons.svg               # 上游线性图标的按需 SVG symbol 集合
    brand.ico               # 复用项目既有品牌图标
    ui-tokens.css
    ui-tabler-adapter.css
    admin.css               # 页面布局及锁定版本的集中适配
    ui-core.js              # 外壳、浮层和通知
    admin.js                # 校验、提交、离开保护与列表状态
    qq-group.js             # 扫码和选群
    ui-components.js        # 仅验收页的示例交互
```

`static` 是 classpath 目录名，不意味着访问 URL 必须带 `/static`。资源 URL 应由统一基址或正确的相对路径生成，并在应用部署上下文中验证；不能把磁盘路径直接搬到 HTML。

### 12.1 依赖与加载

锁定一个已验证的 Tabler 版本，记录文件版本和许可；不使用 `@latest`。只加载实际使用的插件。Tabler JavaScript 已包含 Bootstrap JavaScript；使用该构建时不要再重复加载 `bootstrap.bundle.js`，否则组件事件可能重复绑定。[R1]

加载顺序统一为：**Tabler CSS → ui-tokens.css → ui-tabler-adapter.css → 极少量页面样式**；脚本使用 `defer` 或统一入口，按依赖顺序初始化。不要修改 vendor 文件。

### 12.2 样式分工

`ui-tokens.css` 是项目设计变量契约；所有项目新增规则使用 `--ui-*`，避免散落色值和尺寸。`ui-tabler-adapter.css` 在 `.ui-scope` 内覆盖公共组件与外壳。将 `.ui-scope` 放在 `body` 上，使模态框等挂载到 body 的元素仍在同一主题范围内。

不要假定不同 Tabler 版本或其他 Bootstrap 构建的变量前缀完全相同。新增原生变量映射前，检查所锁定版本实际 CSS；配套基础覆盖使用公共类名和显式属性，不依赖未验证的原生变量名。组件升级必须跑公共组件页回归。

不能靠一条全局 `!important` 修改全部组件，也不能把 `<img>` 截图当成可操作界面。所有文字、输入、表格和按钮必须是真实 DOM。

### 12.3 公共组件映射

| 项目组件 | 基础能力 | 补充内容 |
| --- | --- | --- |
| 页面外壳 | Navbar、Collapse、Dropdown | 双层结构、容器、导航选中态、实际高度同步 |
| 内容面板 | Card | 统一间距和边框 |
| 表格 | Table、Checkbox、Pagination | 查询状态、选择管理、排序、空态、局部滚动 |
| 表单 | Form controls、Validation | 标签规则、错误关联、加载与离开保护 |
| 模态框 | Modal | 统一尺寸、内容和操作布局、焦点与关闭策略 |
| 抽屉 | Offcanvas | 统一宽度、标题、滚动与焦点策略 |
| 提示 | Alert、Toast、Tooltip、Popover | 去重、时间策略、可访问播报、挂载范围 |

Tabler 的外观组件不等于完整的数据表格或表单工作流。筛选、异步状态、未保存保护和动态通知等需在统一交互层实现。动态插入内容后统一初始化，并在移除时释放实例；不要重复绑定事件。

### 12.4 当前接入范围

服务端保留 Spring Boot + Thymeleaf，页面直接加载本地固定版本的 Tabler 1.6.1，不增加 Node 构建步骤。Tabler 内含 Bootstrap 5.3.8 / Popper 2.11.8；图标使用 Tabler Icons 3.49.0 的按需子集，许可见 [服务端第三方依赖](../../server/THIRD-PARTY.md#管理界面资源)。

- 本规范仅作用于服务端管理页面；[启动器 UI](ui-handoff-v1.1.md) 保持独立的 WPF 设计，不全局混用两套变量。
- 已接入首页概览、账户、会话、公告、称号、账户称号、操作记录、QQ 群、管理员密码、登录、一次性密码和错误页。首页 `/admin` 为登录默认入口，首次登录仍强制改密；其他既有路由、字段和权限保持，组件验收页不进行业务操作。
- 首页使用三张账户摘要卡、当前公告与群校验双列面板及最近 5 条操作记录；窄屏回流单列。统计覆盖全部账户，在线判定与账户列表一致；当前公告复用发布快照，群凭据仅展示最近检查状态。刷新使用普通页面导航，不模拟实时更新或添加图表。
- 列表沿用现有每页最多 50 条及上一页/下一页协议，不虚构总数、不新增业务排序或批量操作。查询/重置回到第一页，返回列表恢复同一标签页的查询 URL 和滚动位置。
- 公告、称号及群配置表单增强提交，保留服务器校验失败或网络故障时的输入；确认后的成功重定向才结束编辑。其他表单保留普通 POST。一次性密码仍经原生跳转消费一次，离页时清除显示；密码输入不回显或持久化。
- 未保存保护作用于可编辑表单；链接跳转使用同一确认框，关闭/刷新使用浏览器离开提示。草稿只在当前 DOM 内存中保留，不写磁盘或浏览器存储。
- 成功结果以服务端返回页面或持久 Alert 为准；Toast 公共能力在组件页验收，不在业务操作发出前模拟成功。QQ 扫码请求保留代次隔离，超时显示重试说明。
- 严格保持 `script-src 'self'` / `style-src 'self'` / `img-src 'self'`。复选框和选择框使用原生控件，集中移除 Tabler 内联 SVG 遮罩，不为样式放宽 CSP。所有页面资源和 QQ 请求基址由 Thymeleaf 生成，支持非根部署上下文。

## 13. 交付与验收

管理员登录后打开“组件验收”（`/admin/ui-components`），先检查公共组件，再检查业务页面。验收页至少覆盖外壳、按钮、输入、表格、标签、菜单、模态框、抽屉、Toast、持久提示及空/错/加载状态；每类控件展示完整状态，不只展示默认状态。

验收以配套 [管理 UI 验收表](admin-ui-checklist.md) 为准。无法完成的项目记录原因和后续处理，不将“看上去接近效果图”视为全部完成。
