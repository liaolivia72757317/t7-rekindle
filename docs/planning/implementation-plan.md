# 实施与验收计划

项目按“先完成人机对战，再支持局域网联机”的顺序推进。本计划定义阶段目标和完成条件；当前功能与操作见[使用说明](../requirements.md)，已有基础和待办见[任务清单](task-list.md)。

一项能力需要分别看代码实现、自动化测试和真实客户端表现。具体版本的验收记录应包含提交号、产品包版本、Windows 环境、客户端基线、步骤和结果。

## 第一阶段：可重复的人机对战

先限定一张地图和一种固定模式，按以下顺序补齐：

| 工作项 | 目标 | 完成条件 |
| --- | --- | --- |
| 启动与生命周期 | 稳定目录预检、服务就绪、客户端启动和清理 | 真实客户端完成启动、早期取消、正常退出、异常退出、结束游戏与再次启动；没有遗留的本次客户端进程 |
| 接入与进图 | 贯通登录、大厅、建房、阵营、选将、加载和出生 | 真实客户端可重复完成“启动 → 登录 → 大厅 → 建房 → 选将 → 进图 → 出生 → 离房 → 返回大厅” |
| 移动与场景交互 | 稳定镜头、转向、连续移动、跳跃、落地和碰撞 | 地面、坡道、障碍物场景通过验证，重复进图后行为一致；阻断游玩的悬空和穿透问题得到解决 |
| AI 对抗 | 实现感知、移动、追击、攻击与状态同步 | 敌方对象能够发现、追击并攻击玩家；新一局不残留上一局 AI 状态 |
| 战斗闭环 | 完成命中、受击、生命值、死亡、比分和结算 | 玩家与 AI 对抗能产生一致的战斗结果，并按胜负条件结算 |

第一阶段的整体完成条件是，真实客户端能够反复完成：

> 进入地图 → 人机战斗 → 结算 → 返回大厅 → 再开一局

敌方对象可显示、单条战斗消息可编码或一次启动成功，都不代替上述完整流程。

## 第二阶段：局域网联机

在人机对战稳定后，再扩展当前本地单会话模型：

1. 设计并实现主机提供服务、其他玩家连接及创建或加入房间。
2. 支持多玩家身份、阵营、选将、准备和共同进入地图。
3. 由服务端统一维护移动、AI、伤害和比赛状态。
4. 处理玩家离开、断线、网络延迟和重复开局。

进入本阶段前先评审连接方式、多玩家身份和状态同步边界；当前回环监听不是可直接对外部署的多人服务配置。

完成条件：至少两台真实客户端在同一局域网内完成对局、结算、返回大厅和再次开局；各端观察到的关键比赛状态一致，并覆盖离开、断线和延迟场景。

## 验证矩阵

| 层级 | 验证内容 |
| --- | --- |
| 源码与构建 | 新准备的工具环境可构建；项目引用、锁定还原、Debug/Release 和包布局正确 |
| C++ | ABI 布局、非法输入、动态端口、服务就绪、取消、重复 Start/Stop、清理失败、背压、timer、日志 cursor/gap |
| 托管 harness | 设置持久化、ViewModel 状态、目录选择、关闭流程、SafeHandle、轮询、主题和布局 |
| Python | 业务状态转换、协议编码、玩家名称、构建及打包校验；使用合成 fixture |
| 合成集成 | 独立原生宿主加载 CPython，三通道分片 AUTH、模拟客户端生命周期和诊断；报告保持 `realClient=false` |
| 真实界面 | 键盘操作、UI Automation、高对比度、不同 DPI、窗口缩放及错误提示 |
| 独立产品包 | 无源码和系统 Python 的环境下运行，验证中文及空格路径、DLL 加载、安装和卸载 |
| 真实客户端 | 支持基线上的登录、场景、生命周期和当前阶段的实际玩法 |

新增功能和修复优先使用 RED → GREEN → 重构。可测核心覆盖率目标为至少 80%，属于目标而非当前已达到的结论；报告实际覆盖范围，不用用例数代替覆盖率。

## 发行验收

正式发布前需核对：

- 原生、托管、Python 和合成集成测试通过，报告与发布提交一致。
- 产品包校验通过，Python、托管依赖和许可齐全，不包含游戏客户端或资源。
- 在声明支持的 Windows x64 环境完成安装、启动、升级替换场景和卸载验证；用户设置、诊断和客户端不被误删。
- 真实界面和支持客户端的专项验收有记录；发行说明明确哪些玩法已验证、哪些仍未完成。
- 启动器、安装器和版本日志一致，项目及下载信息有效；示例更新提示与实际发布能力区分清楚。
- 完成应用与安装器签名及签名验证，记录分发文件和对应版本。

当前 tag 工作流在构建通过后自动发布 GitHub Release，并未执行上述全部人工验收或应用签名。这些是正式发行前需完成的工作，不是已生效的 CI 自动门禁；现有行为见[开发与交付](../development.md#5-ci-产物与正式发布)。

开发测试包可用于限定场景的验证，但应明确已知限制，不能仅因使用 Release 构建配置就称为可完整游玩的正式版本。

## 后续方向

在人机和局域网基础稳定后，再逐步扩展本地角色、装备、进度保存、存档备份与恢复、更多地图和模式，以及游戏内感谢名单。具体安排随实际验收结果调整。
