# 电脑玩家 AI 升级规划

T7R 的电脑玩家采用“武将专属作战策略与定位、小队协同、战场调度”的分层体系，不沿用旧性格分类及其策略约束。个人与局部团队决定怎样打，战场指挥根据预训练的地图、模式和任务知识决定在哪里打、投入多少人；两者共用战斗规则，但分别评价和训练。

本规划面向后续 Rust 战斗服，定义行为、职责、数据需求和验收顺序，不规定代码结构、函数、通信字段或训练框架。固定策略先形成可用基线，再逐步接入学习策略；训练、上传和模型发布见[双方向训练与模型演进](computer-player-ai-training.md)。下文新增行为属于升级目标，不表示当前已经交付。

## 当前基础与规则基线

| 领域 | 当前基础 | 升级要求 |
| --- | --- | --- |
| 武将与装备 | 36 名先锋、119 种近战武器／盾牌；另含徒手，共覆盖 246 个非盾武将／武器组合 | 为每名武将建立策略与定位档案，共用装备能力和合法动作基础 |
| 现有电脑 | 开局从全部可出战先锋随机选将，使用各自默认装备，复活保留；按当前武器估计接敌间距，仍使用进攻／全能／防守／疯狗四类性格，主动动作以四向普通攻击和格挡为主 | 旧分类及对应策略不作为新体系约束，以武将策略、装备、熟练度与团队职责组织行为 |
| 攻防 | 按实际配置推进动作；支持蓄势、预输入、挡反、攻防性能、格挡值、盾牌耐久和受击分支 | 理解动作合法性与不同资源，避免把所有反馈当成同一种等待 |
| 伤害 | 使用武器属性、护甲、部位、蓄势、速度、友军衰减、顺劈和已绑定特性 | 决策估计收益与风险，最终命中和伤害仍由战斗规则裁决 |
| 协作 | 已有围攻分流、短期站位、支援、追击保护、巡逻与脱困；小队及队友周边复活尚未实现 | 纳入正式小队关系、局部配合、返场接应与阵营级兵力调度 |
| 运行时 | 当前生产路径使用 Rust；C++ 负责原客户端适配，Python 仅供开发对照 | 迁移验证战斗规则、物理输入与生命周期一致；新 AI 策略独立验收，不要求复现旧性格行为 |

装备范围与参数依据为[先锋阵容与武器配置](../loadouts.md)，攻防依据为[近战攻防规则的当前战斗逻辑](../combat-rules.md#当前战斗逻辑)。现有 AI 的动作选择与默认装备可从 [bot_decision.py](../../tests/reference/Business/scripts/bot_decision.py) 和 [bot.py](../../tests/reference/Business/scripts/bot.py) 核对；这里只将它们作为现状证据，不要求 Rust 沿用其组织方式。

[电脑玩家说明](../computer-player.md)和[旧 AI 优化交接](computer-player-ai-handoff.md)包含不同阶段的记录。以下旧描述不作为本次升级的规则基线：

- 普通攻击／冲刺固定扣 `20/40`：当前已改为属性与倍率结算。
- 普通格挡按四向枚举配对及固定正面角度保证成功：当前以真实防御武器／盾面接触及性能判定为准；挡反另有配对和时间窗口。
- 所有武器沿用相同出招窗口或固定收招前 `100 ms` 关闭：当前读取武将／武器动作配置。
- 看到对手收招便视为固定安全期：当前普通收招可以被合法攻防输入衔接或取消。
- 所有反馈都允许持续移动：当前移动锁定、击倒与动作恢复分别处理。

初期仍围绕洛阳死斗、最多 20 个角色、每局默认 20 分钟与阵营 60 杀目标验证。战略知识按地图、游戏模式和任务目标分别规划，后续内容以对应模式正式规则为前提；不借 AI 升级新增远程、坐骑、技能、成长数值、据点占领或其他胜负规则。小队复活作为已确认的规划目标单独接入，不视为当前已有能力。

## 两个方向与三层决策

| 训练方向 | 决策层 | 负责的问题 | 输出 |
| --- | --- | --- | --- |
| 作战策略 | 个人作战 | 按武将定位与当前装备怎样接敌、攻防、管理资源和脱离危险 | 合法的移动、朝向、攻防及装备使用意图 |
| 作战策略 | 局部团队协同 | 小队如何配合、与邻近友军如何协同、谁接应复活成员 | 局部职责、共同目标、站位与返场配合意图 |
| 战场调度指挥 | 阵营指挥 | 怎样运用预训练战略知识分配小队与兵力，何处增援、转移或返场 | 有期限的区域任务、人员分配、路线意图与撤销条件 |

局部团队与战场指挥分开：前者处理眼前一场交战，后者权衡多处交战和整局目标。指挥不逐刀决定攻击方向，不强制角色放弃眼前防御；个人也不因发现一个近敌就无限偏离支援任务。

规则层先约束所有意图。冲突处理按以下顺序：

1. 比赛与生命状态、观测有效性、动作及移动限制。
2. 局部即时威胁、合法防御和脱困。
3. 当前交战的个人与团队战术。
4. 指挥任务的执行与返场路线。

低层可因即时威胁暂缓任务，并反馈原因；危险解除后重评原任务，不每次自行遗忘。指挥任务失效则释放人员，恢复局部交战、搜索或巡逻。真人是自主参与者，AI 可以配合其可见行动，但不接管真人输入，也不假定真人必然执行任务。

## Rust 与其他实体的职责

沿用[目标架构](target-architecture.md)与[战斗公共契约及资源数据包](../battle-contracts.md)，AI 不另建一份战局真相。

| 实体 | AI 相关职责 |
| --- | --- |
| Rust 战斗核心 | 战斗规则、感知边界、三层策略、动作合法性、任务状态和最终结算；接入小队机制后统一裁决成员关系、交战状态与复活资格，AI 只提交意图 |
| Rust 宿主 | 调度、资源、已批准模型与战略知识的加载、运行预算、采集出口；训练和上传不阻塞战斗循环 |
| 启动器与兼容适配 | 执行本机角色／指定 AI 的物理采样、转换语义意图、管理本地采集与上传选择；不独立裁决 AI 命中 |
| Java 平台 | 在线房间、配置与版本分配；如接入数据接收和模型审批管理，仍不承担实时指挥或逐动作推理 |
| 离线训练环境 | 数据处理、两个方向的训练、地图／模式／任务战略知识构建、评测及候选产出；不成为玩家开局依赖 |

Windows 进程内与 Linux 节点使用相同策略语义。AI 不持有客户端内存布局、原协议 RID 或本机资源路径；所需装备与导航来自同版本资源输入。协议补充按既有公共契约单独评审，本规划不新增另一套消息格式。

本期仍是客户端采样、Rust 裁决。AI 路点不等于已到达，攻击预判不等于刀刃命中；Rust 不因加入学习模型而获得服务端物理模拟。多人采样归属与采样者退出处理继续遵循[三模式计划](battle-network-v1.md)。

## 武将专属策略与装备能力

### 每名武将的策略档案

36 名武将分别建立策略档案，不再绑定旧性格模板。差异来自实际属性、合法装备、动作与已生效特性，以及由此适合承担的战场职责；不为制造差异而增加隐藏加成或虚构技能。

| 档案内容 | 需要明确的策略 |
| --- | --- |
| 战场定位 | 主要与次要职责，例如正面承压、施压突破、侧翼切入、反制拦截或支援接替；注明适用条件与短板 |
| 个人作战 | 合适接敌距离、选向与蓄势倾向、防御和资源管理、优先对手及不利对局的处理 |
| 装备分支 | 当前主副手对策略的影响，破盾、资源耗尽及后续合法换武器后的调整 |
| 小队配合 | 适合搭配的队友能力、进攻空间需求、牵制与接替方式，以及临时承担返场接应的条件 |
| 指挥适配 | 在不同地图、模式和任务中适合的分路、增援、守路或转移职责 |
| 评价场景 | 能证明该武将定位有效的典型对局，以及应当调整定位的反例 |

定位不是永久职业锁：同一武将可以随装备、地图和队伍缺口承担不同任务，能力相近的武将也可以共享职责。各档案复用动作、能力评估与协同基础，不要求为每名武将各建一套决策引擎或独立模型。熟练度单独控制判断质量与失误，不替代武将定位。

### 能力画像

每个合法武将／当前装备组合应能回答以下问题，答案来自现有规则和资源，不从武器名称或外观猜测：

- 有哪些方向攻击，准备、出招、接触窗口、反馈和换武器各持续多久。
- 能否普通格挡、举盾、挡反、冲刺；当前副手是否可用。
- 各方向可用伤害类型、攻防性能、相对重量、护甲类别及真正生效的特性。
- 生命、格挡值、盾牌耐久、增益和动作／移动锁定各是什么状态。
- 在哪些距离、相对角度和地形下存在可靠出手机会，哪些情况缺少足够证据。

攻击距离不直接用静态刀刃长度或全武器统一的 `2 m` 得出。升级需要按武器动作族采集有效接敌距离与方向覆盖，再验证不同角色绑定；这些是规划用的保守估计，不替代真实接触。未完成验证的组合先限定使用范围，不套用另一把武器的极限距离。

### 可复用的装备行为倾向

| 装备与特性 | 策略应体现的差异 |
| --- | --- |
| 短兵器、快起手 | 寻找安全贴近和短窗口，不在长兵器优势距离持续挥空 |
| 单手武器与盾牌 | 兼顾举盾起手、成功反馈、格挡值与耐久；破盾后立即按失去副手重评 |
| 双手与高攻击性能武器 | 利用性能差和适用蓄势施压，付出真实准备时间，不默认每刀都抢得过快武器 |
| 长柄与反制 | 管理纵深和友军遮挡；反制只评价命中时目标正在 Strike 的机会，不把其 Prepare／Hold 当成触发条件 |
| 钝伤与刺伤组合 | 根据目标护甲和实际基础属性比较收益，不采用“重甲一律换某武器”的硬编码 |
| 势大力沉、蓄力精通 | 识别满蓄势收益、性能跨级和暴露风险；下刺及其他未绑定加成不凭空提升性能 |
| 顺劈与刺客 | 优先利用已有多目标或侧后方机会；不为追求绕后而放弃眼前有效攻击 |
| 反击、连击、狂怒、逆境 | 使用实际事件触发与有效期；不为触发增益主动刷伤、送死或攻击友军 |

上述倾向是武将档案的共用依据，而不是新的固定性格分类。进攻意愿、防守选择和追击边界由武将策略、当前装备、任务与战况共同决定；不保留旧类型的强制不防守或特殊索敌策略。

### 阵容与生命周期

先让电脑从当前合法先锋及其装备集合生成本局配置，验证名单、模型、动作、属性、死亡复活一致，再调阵容多样性。开局组合应覆盖不同武器职责，双方遵循相同生成约束，不把人类所在阵营固定设为弱方或强方。

第一批多装备 AI 在本局复活时保持既定武将与装备，以隔离行为升级效果。后续如启用复活重选，只在开局冻结的阵容内选择，并在死亡后的合法选将边界生效；不在存活时替换武将，也不临时取得快照外的克制装备。

小队关系与角色生命分别管理：死亡释放当前动作与执行承诺，不自动退出小队；复活后的任务重分配考虑小队现状。后续重选武将可以改变作战定位，不隐式改变小队归属。

战斗中换武器属于后续能力：只在动作规则允许且有足够安全窗口时使用，计入真实切换成本，设置收益门槛与保持期以避免反复切换。盾牌损坏不因切换恢复，复活恢复依照既有规则。

## 个人作战升级

### 感知与威胁

使用观察延迟、目标记忆和切换滞回控制自然反应与稳定性，参数由新策略和难度重新评价，不照搬旧性格阈值。区分“攻击目标”和“即时威胁”：附近第三人正在形成危险时，允许先朝向、格挡或移动应对，不必立刻把长期追击目标也切换过去。

威胁评价结合可观察的动作阶段、武器能力、距离、接近速度、地形、预计接触区间和自身脱离空间。不要只因对手出现准备动作就无限等待，也不要因某个固定阶段余量阈值自动判定安全。

AI 可准确读取自身资源；敌方信息只使用已允许观察到的内容。未公开的剩余格挡值、盾牌耐久、缓存输入和未来松键时刻不成为精确特征；需要时根据已见动作和结果维护带不确定性的估计。

所有新策略遵循同一信息边界。预训练可以知道地图结构、公开模式规则和资源分布，但不因此知道本局隐藏敌人的位置、意图或资源；旧策略的全图索敌不迁入新体系。

### 攻击与动作衔接

- **选向**：综合接触机会、真实准备时间、伤害类型、敌方防御姿态、附近友军和地形，不再以机械避免重复方向为首要目标。连续同向在有效时可以成立。
- **蓄势与压刀**：区分快速释放、短暂延迟与峰值蓄势。当前峰值为 Hold 后 `600 ms`，不是按下攻击后的总时间；超过峰值不持续增伤。根据威胁变化提前释放或合法转防，避免所有角色每刀固定等满。
- **收招追击**：评估自身起手和接近成本，对普通可取消收招只作机会估计；对明确的被招架、受击等反馈也要比较剩余窗口，不把“还在反馈”当作必中。
- **预输入**：按现有单槽、保持与松键语义规划下一动作；不得把单槽扩展成多步连招队列。准备／Hold 转防、Recovery 衔接与 Strike 内缓存分别处理。
- **取消与承诺**：新威胁只能通过已有合法输入改变动作。学习策略同样不跳过准备、不缩短硬直、不取消不可取消的 Strike。

### 普通格挡、挡反与资源

普通格挡关注实际防御覆盖和敌我攻防性能；挡反在防守方攻击 Prepare 阶段评估方向配对与双方攻击性能，覆盖进攻方整个 Strike 的有效接触窗口。方向建议只用于形成姿态，成功与否仍取决于实际防御几何接触。

固定持盾／持挡时长改为结合威胁结束、反馈、后续来袭和资源的判断：攻击尚在 Hold 时不因定时到点机械松挡；危险解除后也不无故长时间举武器。改变防御方向仍须遵循松开再按下的规则。

生命、格挡值和盾牌耐久分别管理。性能直接破防、格挡值耗尽和盾牌破损也分别处理：

- 性能差过大时，比较减伤防守、脱离和抢攻的实际风险，不把“挡住姿态”视为免伤。
- 格挡值偏低时，寻找脱离连续压制或主动有效进攻的机会；命中／被挡恢复的收益不计入挥空、友军或地形接触。
- 格挡值耗尽与盾牌耗尽的最后一击仍按原规则吸收，之后才进入相应反馈；AI 不提前判定该击直接扣血。
- 盾破、击倒、移动锁定、普通受击与武器反弹分别更新行动许可；重甲也不等于免伤或永久霸体。

冲刺、跳跃与蹲伏按能力验收后逐项加入。尤其跳跃会锁定空中朝向和移动，且存在被击倒风险，不因轻盈加成便默认连续跳攻。联机首期尚未接入的动作不因单机已支持而直接开放给联网 AI。

## 局部团队协同

以游戏的小队成员关系组织持续协作，同时允许同一交战区域内跨小队临时配合。正式小队与临时战术分组分开：一起围攻不等于加入小队，也不产生队友周边复活资格。小队机制尚未实现，现阶段先使用已支持的邻近友军协同；成员关系和复活能力完成规则接入后再启用相关策略。

局部职责结合武将档案、装备、位置、生命和资源分配，并保留短期承诺，避免每个决策周期互换位置。小队规模、编组与变更方式沿用后续确认的游戏规则，不由 AI 为取得复活便利自行重组。

| 职责 | 主要行为 | 结束或交接条件 |
| --- | --- | --- |
| 正面牵制 | 面向主要威胁，利用可靠防御维持接敌面 | 资源不足、侧后方受压、队友接替或目标失效 |
| 施压进攻 | 利用性能、起手或蓄势优势创造对手防御负担 | 攻击通道被挡、被集中威胁或出现更高优先级防守 |
| 侧翼进攻 | 利用已有侧向空间，减少撞到防御武器的机会 | 路线成本过高、地形阻断或近处已有有效出手机会 |
| 支援与接替 | 减轻队友被多人围攻的压力，接替资源不足者 | 队友安全、敌人转移、任务过期或自身危险升高 |
| 外围接敌 | 在内圈拥挤时控制可达通路，接应增援 | 出现有效攻击通道或需要转移到另一交战区 |
| 返场接应 | 小队机制启用后，由适合且未交战的成员临时提供周边复活机会，兼顾落点与撤离通路 | 队友完成返场、接应者进入交战、位置不再适合或参战收益更高 |

协同重点从“站得分散”升级为“攻击线路有效”：

1. 友军虽不掉血，却会令后续伤害衰减至 `0.4/0.05`、攻击性能降为 F；长柄和横扫都要考虑刀路上的友军，而不只检查最终落脚点。
2. 顺劈依据武器实际穿透能力评估，防御武器拦截或墙面仍可能提前终止整刀；不把多个敌人排成一线直接计为多杀。
3. 空间拥挤时优先让出通道、换向、错开机会或分流目标；不使用全队定时停手，也不为等待完美编队延误已有机会。
4. 受击、资源耗尽或被夹击的队友可以触发支援，但支援通过实际移动和攻击实现，不引入嘲讽、治疗或强制转移敌方目标。
5. 支援承诺考虑已有支援人数及预计到达时间，避免多个小队同时追向同一个已结束的战斗。

同一局内，友方与敌方采用同样的身体避让、信息限制和协同规则。玩家位置参与通道检查，但 AI 不要求玩家让位，也不根据未提交的玩家输入提前避开。

### 小队复活与返场

规划中的机制是：死亡成员在满足复活条件时，可以在同小队、存活且未进入战斗的成员周边复活。接应者只是候选复活参照，不获得治疗、复活技能或额外保护；AI 也不直接移动死亡角色或跳过死亡等待。

- **接应取舍**：结合待复活成员、预计返场收益、接应区域风险和少一人参战的代价，决定是否暂留接应者。职责可交接，不固定某名武将永久躲藏。
- **选择与执行分开**：选择时符合条件不代表执行时仍合法。实际复活前重新确认小队关系、接应者生命与交战状态、当前位置和有效落点；进入交战、死亡、离队或失效后重新选择或按该模式规则处理。
- **落点约束**：周边位置还须满足地形、可达性、楼层和身体占位等规则，多人同时返场也须避免重叠与堵塞；风险估计只使用允许观察到的敌情。
- **重新加入战斗**：返场后依据武将定位和小队当前任务分配职责，不机械恢复死亡前的追击目标，也不把全队集结设为重新参战的必要条件。

“未进入战斗”须由统一战斗状态判定，不以站立、未攻击或暂时看不到敌人代替。交战进入／脱离条件、脱战等待、复活半径、同时人数、复活等待与选择方式、保护及无有效接应者时的处理，均在小队规则接入前确认，本规划不预设数值。能力未启用时继续采用当前阵营复活规则，不生成虚假的小队复活动作或训练结果。

## 战场调度指挥

### 离线战略知识与局内修正

地图要点、通路和真实存在的关键资源不在每局从零发现、重新评估。按**地图版本、游戏模式、任务目标及阶段、战斗规则**建立离线战略知识，预先评估稳定价值和条件化行为，再经评测与人工批准随策略发布。

| 战略知识 | 离线评估或预训练 | 局内需要修正的内容 |
| --- | --- | --- |
| 地图要点与通路 | 区域连接、瓶颈、侧翼与撤离路线、基础通行时间、适合交战或集结的位置 | 拥堵、实际路阻、已报告敌情、当前可投入兵力 |
| 模式与任务目标 | 胜利条件、任务依赖、阶段优先级、分路与开局计划、终局风险取舍 | 比分、剩余时间、目标进度及任务失效 |
| 关键资源 | 对应模式确实存在的资源位置、用途、获取规则及条件价值 | 当前可用性、争夺风险、队伍需求和获取成本 |
| 武将与小队适配 | 不同阵容适合承担的任务、互补组合和路线选择 | 本局装备、生命与防御资源、已承担任务和人员损失 |
| 返场接应区域 | 小队机制启用后，可预评估接应区域与返场路线的潜在价值 | 实际队友资格、位置、落点可用性和临时敌情；不把区域直接当作合法复活点 |

静态拓扑、公开规则等确定事实通过离线整理与计算获得；有不确定性的区域价值、任务排序和行为方案再由场景评估与训练改进。产物保留适用条件、候选方案与可信范围，而不是一张永远不变的要点排行榜。

开局加载匹配版本的知识并选取适合阵营、阵容和任务阶段的方案，局内只结合变化的态势修正价值与选择。地图或规则变化使知识失配时停止使用对应产物，按兼容规则策略运行；不在本局临时训练替代版本。当前洛阳死斗先评估接敌、通路、兵力交换和返场价值，不虚构资源、占点收益或攻城任务。

### 战场认识

指挥层以地图的可达区域和连接关系组织战场，而非以全体敌人实时坐标作全知决策。维护己方可用兵力、任务承诺、复活返场情况、已报告交战区域、敌情更新时间、比分和剩余时间。

敌情由符合信息边界的团队报告汇总，失去观察后置信度衰减，最多表示“此处曾有威胁”。未知区域不等于无人区域；导航可达不等于视线可见。预训练的战略重要性也不代表该区域本局必有敌人或值得立即投入全部兵力。

### 调度任务

| 任务 | 触发依据 | 主要约束 |
| --- | --- | --- |
| 分路接敌 | 开局暂无可靠交战，或原战斗已结束 | 保留接应能力，避免全员拥堵同一路口 |
| 局部增援 | 己方局部劣势，且增援预计在交战结束前到达 | 计算路程、可抽调人数和原区域代价，不只选直线最近者 |
| 有限集结 | 己方复活分散，持续逐个投入导致劣势 | 只调整返场路线和有界集结等待，不推迟既有复活时刻 |
| 转移接战 | 当前区域成本高、通道拥堵或目标已经失效 | 保留正在执行的合法动作及即时防守，不整队同帧掉头 |
| 脱离与接替 | 伤亡风险高于继续战斗收益 | 以可达退路及队友接应为前提，不要求穿过敌人撤离 |
| 小队返场接应 | 启用小队机制后，合法接应可改善小队重新投入的时机与位置 | 动态比较返场收益与少人参战代价，不为保持接应而无限脱战 |
| 目标与资源调度 | 对应模式启用目标或资源后，按预训练的阶段价值与局内变化分配兵力 | 只处理真实存在且当前有效的目标，不沿用其他模式的收益 |
| 终局取舍 | 比分、剩余时间与击败目标改变可接受风险 | 领先不等于全队无限藏匿，落后不等于无脑逐个送入 |

当前是击杀制死斗。区域与通道用于调兵，不额外赋予占点分数、资源产出或攻城目标。击杀数、局部人数与武器互补共同辅助判断，单次伤害最高者不自动成为所有兵力的唯一目标。

### 指挥稳定性

每项任务需要明确目的、参与者、目的区域、优先级、建立时间、预计有效期与成功／撤销条件。小队机制启用后优先按小队协调，也可向部分成员分配支援任务；任务分配不改写正式小队关系。接令者反馈接受、途中、接战、完成、受阻或临时中断；这些是业务语义，不在本次固定消息格式。

重分配采用收益门槛和短期保持，考虑已经在路上的兵力；重大伤亡、通路失效或任务目标消失才触发必要的提前重评。任务结束、死亡、离场和新局释放承诺，不留下永久占位的“幽灵增援”。

先建立规则指挥基线，再训练指挥模型。现有记录没有真实指挥命令时，不把若干角色恰好同时移动解释为人类下达了集结命令。

## 调度、难度与解释

采用快慢分层，已有节奏仅作为工程预算起点，不要求继承旧策略；不以语言迁移或模型推理取代动作时钟：

| 工作 | 规划节奏 |
| --- | --- |
| 个人战斗响应 | 以现有 `100 ms` 快层为迁移基线；状态变化可标记重评，但反应时间仍从实际观察开始 |
| 目标、局部协同与路线规划 | 以每人 `500 ms`、错峰执行为基线；复用同一时刻的有效观测 |
| 阵营指挥 | 加载预训练知识后，初始建议约 `2 s` 更新动态态势与任务，并合并重大事件；不逐局重建静态战略评估，最终周期经负载和任务稳定性验收确定 |
| 位姿、接触与动作恢复 | 延续原生观测和独立动作时钟，不取整到策略或指挥周期 |

学习模型只参与已到期的策略工作，常驻使用已确认版本；超时、未知装备或输出失效时按同一信息边界回退到规则策略，不额外延迟一次攻防。采集和模型性能预算纳入[迁移计划的产品切换门槛](rust-runtime-migration.md#产品切换门槛)，不通过降低 AI 频率、丢输入或推迟动作来过关。

难度通过观察延迟、机会判断、规划深度、协作稳定性和可控失误体现，不修改伤害、动画、命中范围、转向能力或隐藏信息权限。武将定位不等于难度：承担正面防御的武将与侧翼武将都可以具有不同熟练度。

决策记录应能解释“为何未出手、为何保持防御、为何换目标、为何暂留接应、为何拒绝增援”，并关联武将策略、当前小队职责、实际装备、模型／战略知识版本及采样新鲜度。指挥须区分离线优先级与本局调整原因，避免仅用击杀数评价智能程度。

## 实施顺序

| 阶段 | 交付重点 | 进入下一阶段的条件 |
| --- | --- | --- |
| A0 规则与能力清点 | 合法组合、36 名武将策略档案、小队待确认规则、地图／模式／目标知识清单及评价场景 | 每种计划行为都有规则依据或明确的待验证条件 |
| A1 Rust 规则迁移 | 战斗规则、物理输入、导航和生命周期一致；旧 AI 仅作迁移对照 | 回放与性能门槛通过；新策略差异独立验收，不以复现旧性格为目标 |
| A2 武将个人作战 | 武将定位、装备分支、威胁、蓄势、防御资源与动作衔接 | 所有启用组合合法，武将策略符合定位，原有战斗规则未改变 |
| A3 团队与指挥基线 | 已支持的局部协作、任务反馈、地图战略知识与阵营调度；预留正式小队和返场职责 | 分别验证协作、知识复用和调度效果，未实现机制不成为动作前提 |
| A4 数据与影子评测 | 主动开启采集、脱敏上传、双方向数据集、候选策略只记录不执行 | 数据可追溯、无未来信息泄漏，不影响现有战斗时延 |
| A5 学习策略试点 | 个人／团队与指挥分别训练、交叉评测、人工审批 | 兼容策略组合通过实战与工程门槛，仅新对局生效 |
| A6 能力扩展 | 小队关系与周边复活完成规则接入后联调；按模式扩展冲刺、换武器及必要的复活重选 | 每项能力完成规则、采样、执行、策略与联机一致性验收后独立启用 |

武将档案、离线战略知识、数据语义和评测场景可以随架构调整并行规划；生产级采集依赖稳定的战斗事件，模型执行依赖对应能力完成接入。小队能力完成后可独立进入联调，不要求等待学习模型，也不阻塞已有能力升级。AI 升级与模型训练均不成为完成 Rust 规则迁移的前置阻塞。

## 验收矩阵

| 范围 | 场景与通过条件 |
| --- | --- |
| 装备覆盖 | 遍历 36 名先锋、119 种近战武器／盾牌及徒手的合法绑定；246 个非盾组合和合法盾牌搭配分别覆盖，不对任意武将开放任意武器 |
| 武将策略 | 每名武将都有定位、装备分支和典型场景，分别验证主要职责与不利对局；不依赖旧性格模板或其特权索敌 |
| 能力差异 | 短兵器对长柄、单手盾对双手、轻／中／重甲对不同伤害类型；不共用默认距离、动作时长或防御成功假设 |
| 蓄势与衔接 | 立即释放、峰值附近释放、过峰、准备转防、合法预输入和收招衔接；行为收益来自规则而非加速动画 |
| 防御资源 | 普通格挡、挡反、性能破防、格挡值耗尽、盾破、连续反馈分别正确；晚到反馈不重新举盾或重复恢复资源 |
| 多人威胁 | 面对当前目标时第三人来袭，保护自己但不反复抢目标；围攻中不把一次成功格挡视为全方向免伤 |
| 团队作战 | 友军挡刀、不同顺劈等级、窄路、墙角、队友残血与资源耗尽；比较攻击通道、有效进攻、拥堵和接替效果 |
| 小队与返场 | 正式成员与临时协作对象分开；接应者交战、移动、死亡或离队以及多人同时复活时重新验证；不跨小队复活，不永久藏匿维持接应 |
| 战场调度 | 两处同时交战、增援赶到前目标失效、多人复活、通路阻断、领先／落后终局；兵力承诺有界且及时释放 |
| 战略知识 | 同版本跨局复用静态要点评价，动态变化能修正预案；地图、模式或目标失配时停用对应知识，不把死斗套入占点收益 |
| 信息边界 | 隐藏敌人、失去观察、旧记忆与敌方缓存输入；所有策略不因服务器持有全局状态或离线预训练而获得额外敌情 |
| 生命周期 | 角色死亡、复活、任务取消、结算、新局、模型失败与采样者退出；旧动作、任务和接触不跨生命或战局污染 |
| 性能与部署 | 20 角色同场、多装备、多处交战、采集开／关、规则／学习策略；Windows 与 Linux 采用同一业务语义 |

规则正确性采用硬门槛；策略效果采用同地图、同阵容分布、成对种子与互换阵营的统计比较。固定历史输入适合回归规则，不足以证明改变决策后的闭环战斗更强。需分别报告有效机会空等、挥空、友军衰减、资源耗尽、任务抖动、支援到达、阵营表现和运行时延，避免以单一胜率掩盖退化。

本轮交付是上述规划与训练规划。具体预算、调参区间、接口演进及训练依赖在相应阶段评审后确定，不在架构调整期间提前固化实现。
