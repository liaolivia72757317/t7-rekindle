# 电脑玩家双方向训练与模型演进

自我进化采用“本地战斗采集 → 脱敏上传 → 离线集中训练 → 分层对战评测 → 人工批准 → 新对局启用”的闭环。训练分为两个方向：**个人与局部团队作战**、**战场调度指挥**。两者分别训练和验收，再验证组合效果，而不是把所有任务交给一个逐帧模型。

作战方向以武将专属策略、战场定位及正式小队协作为条件，不继承旧电脑性格及对应策略；小队周边复活在机制接入后纳入训练。指挥方向预先学习地图、游戏模式和任务目标的稳定价值与条件化方案，跨局复用，局内只根据当前战况修正。

已确认的产品边界：玩家明确开启后才采集上传训练数据；仅使用脱敏结构化战斗数据，不含画面、聊天或账号身份；模型集中离线训练，经评测与人工批准后仅在新对局生效。局内允许更新观察记忆和任务状态，不训练权重或热换模型。

本页定义学习目标、数据语义、运行职责、评测和发布流程，不指定实现代码、模型网络、存储格式或框架依赖。战斗规则与固定策略基线见[AI 升级规划](computer-player-ai-upgrade.md)，架构边界沿用[目标架构](target-architecture.md)。

## 两个方向的职责与产物

| 项目 | 方向一 个人与局部团队作战 | 方向二 战场调度指挥 |
| --- | --- | --- |
| 决策对象 | 单名武将、正式小队及附近临时协作对象 | 阵营可用小队、兵力与多个交战区域 |
| 主要问题 | 何时攻防、让位、保护、接替，以及何时承担小队返场接应 | 怎样利用地图要点、真实资源和目标价值，决定接战、增援、集结、转移和脱离 |
| 主要输入 | 武将策略与装备能力、局部可观察历史、小队状态、当前任务、地形与动作许可 | 已批准的地图／模式／任务知识、己方兵力与任务、带时效的敌情报告、返场状态、比分与剩余时间 |
| 输出层次 | 合法候选动作的偏好、局部角色与配合意图 | 区域任务、人员分配、优先级和结束条件 |
| 评价时间尺度 | 一次动作、一段攻防交换、一次局部交战 | 一次任务、多处交战演变、整场比赛 |
| 主要产物 | 武将条件化作战策略及个人／小队协同评测结果 | 分地图、模式和目标的战略知识、指挥策略及调度评测结果 |

方向一内部保留个人和协同两个子目标：单挑成绩提升不代表会配合，团队获胜也不证明每个个体的动作合理。方向二不学习刀刃命中判定，不通过降低个人层反应时间制造“指挥进步”。

两类策略可以复用装备与态势表征，但共享模型不是前提；每名武将有独立的策略档案，也不意味着需要独立训练一个模型。每次发布明确武将档案、作战策略、指挥策略、战略知识、信息规则与战斗版本的兼容组合，支持只替换其中一个方向并独立归因。

## 固定规则与学习策略

固定部分分为两类：

- **战斗约束**：动作合法性、时长、伤害、防御、物理证据、身份与生命周期规则，始终由战斗核心执行。
- **规则策略**：按新武将定位进行选招、目标评分、小队配合与指挥，结合已验证的地图知识，作为可运行基线、训练起点及模型失效时的后备；不以复现旧性格为目标。

学习策略先估计机会与风险，再对合法候选排序；成熟后可扩展策略范围。它不输出最终扣血，不改写接触、不取消规则锁定，也不绕过感知限制。规则策略与模型使用相同信息权限，回退不变成全知模式。

首期优先让模型辅助“命中机会、来袭风险、局部交换结果、支援到达与交战持续时间”等不确定判断。确定的护甲公式、格挡值恢复和动作阶段不需要交给模型重新猜测。

## 数据闭环与责任

| 环节 | 责任与产物 |
| --- | --- |
| 战斗内记录 | Rust 在已提交的输入、观察、决策、任务和结果边界生成训练记录；不在采集端另算胜负 |
| 本地暂存 | 启动器或宿主把允许采集的数据异步整理为有界片段，标记缺口与完整性 |
| 上传 | 玩家选择生效后，经独立上传路径发送；断网不影响离线对局，失败可稍后续传或取消 |
| 接收与整理 | 校验结构、版本、批次、来源与质量，去重并隔离异常数据，建立数据集版本 |
| 战略知识准备 | 从同版本地图、模式及任务定义提取稳定事实，离线评估要点、资源和候选预案；不依赖每局重新探索，也不随玩家记录上传原始资源包 |
| 双方向训练 | 使用相同事实但不同观察范围、时间尺度与目标，产出武将作战、协同及条件化指挥候选与训练报告 |
| 评测与审批 | 与固定基线和历史版本比较，通过分层、组合、性能与实机验收后人工批准 |
| 分发与生效 | 新局选择已批准且兼容的组合，整局固定；发现退化可停止新局采用并回退 |

训练及数据整理属于离线支撑能力，不改变 Java、Rust、启动器、原客户端的战斗权威分工。实时推理在战斗运行位置完成，不逐动作请求云端模型，也不让玩家安装训练环境或在游戏时占用设备训练。

### 玩家选择与上传范围

1. 训练采集默认关闭，与游戏运行必需的即时采样分开。开启时说明目的、字段范围、上传时机、缓存限制与撤回方式；不开启仍可正常游玩。
2. 以开启后的新对局为清晰采集边界；中途关闭立即停止后续训练记录与上传，已有待上传内容允许清除。不得把此前普通诊断日志自动补传为训练语料。
3. 单机只涉及开启者与电脑。LAN／在线的完整团队轨迹涉及其他真人，拟以本局全部真人明确同意作为采集条件；房主开启不代表其他人同意。缺少完整参与条件时不生成完整团队训练局，也不以删掉名字替代参与选择。
4. 单局临时角色编号保留交互关系，不保留昵称、QQ、账户 ID、机器标识、设备指纹、令牌、本机路径或跨局玩家画像。比赛／房间引用转换为训练用临时标识，凭据不进入语料。
5. 不采集画面、声音、聊天、原始内存、客户端程序／资源包或通用日志。只记录游戏语义动作，不记录窗口外按键。资源用兼容版本与公开可解释的资源标识关联，不随记录上传完整资源数据包。
6. 上传接收端应与训练数据隔离管理传输认证及必要运行日志；训练负载不含身份，不等于网络接收过程天然没有 IP 等元数据。保留期限、访问范围与删除流程在试点前明确。

本地和 LAN 上传不要求用平台身份标注样本，也不把上传量转换为在线战绩或奖励。上传回执可用于查询、删除相应批次，但不作为模型的玩家特征。完整对局只指定一个整理来源，避免多个客户端重复贡献同一轨迹。

撤回时停止后续采集与上传，清理本地待上传数据，并根据回执处理服务端原始批次和后续数据集排除。已经训练或发布的模型通过数据谱系定位影响，必要时撤回或重训；删除原始文件不等于已消除模型中的样本影响。

### 不影响战斗的采集

训练记录使用独立、有界的异步出口。磁盘慢、网络失败、队列或容量到限时，允许停止训练记录并标注片段不完整，保持战斗输入、动作与接触处理；不静默丢弃战斗事件来维持数据上传。

基础态势可随现有决策节奏记录，动作、接触、任务变更、死亡复活与结算使用事件记录；短挡反窗口不靠低频状态截图重建。先测每局数据量、写入成本和排队影响，再确定采样密度、分片大小、缓存容量与保留期，不先指定缺少测量依据的带宽预算。

## 两个方向共用的数据语义

| 数据类别 | 必须表达的内容 | 用途 |
| --- | --- | --- |
| 版本与上下文 | 战斗、资源、地图、游戏模式与任务阶段、权威模式、客户端兼容、武将档案、策略／模型、战略知识及采集定义版本；阵容、装备、定位、难度与可重放随机状态 | 区分内容、策略与规则变化，隔离不同模式的收益 |
| 身份与生命 | 单局临时角色与小队编号、阵营、真人／电脑、成员关系变化、生命代次及出生死亡边界 | 保留正式小队关系，隔离跨生命事件，不建立跨局玩家身份 |
| 可用观察 | 决策时真正可获得的对象、动作、资源、地形、记忆、信息年龄与缺失标记 | 构建与推理一致的输入，防止全知和未来泄漏 |
| 行为与执行 | 候选范围、所选意图、观察与决策时刻、规则接受／拒绝、实际开始、打断、保持与释放 | 区分“想做”“允许做”和“实际做了” |
| 战斗结果 | 命中／格挡／挡反／破防／盾破／反弹／空挥、相关部位与接触证据、资源变化、伤害、增益和击杀 | 自动派生学习目标和规则核对，不依赖画面标注 |
| 局部团队 | 正式小队与临时战术分组、武将与局部职责、共同目标、站位承诺、友军挡刀、支援接替及交战起止 | 评价协同，不把临时合作当作正式小队或复活资格 |
| 小队返场 | 机制是否启用、允许观察的待复活与接应资格状态、候选选择、资格变化、执行校验、实际复活位置与后续归队 | 区分接应选择、合法性与实际返场收益；未实现时不虚构事件 |
| 战场指挥 | 适用战略知识及离线价值、当前可见态势与修正原因、候选任务、命令与人员分配、接受／中断／完成、预计与实际到达、任务期间损益 | 区分预训练知识的贡献与本局调度调整 |
| 结果与质量 | 正常胜负／平局／中止、最终比分、缺口、重复、延迟、来源等级、片段截断及能力可用状态 | 区分终局、记录停止、机制未启用与执行失败 |

训练输入、事实标签、审计信息三者分开保存逻辑用途。核心持有的敌方真实隐藏资源、未来接触和最终结果可以用于相应结果核对，但不拼进当时的策略观察；指挥层也只看到按规则上报的敌情。

### 时间与因果关系

- 同时区分事件发生、宿主接收、策略可观察、决策提交和动作执行的时点；统一到本局时钟。输入延迟不是额外思考能力。
- 接触结算按发生时刻和攻击／装备快照关联，训练也沿用该关系；晚到的命中结果不得提前放进此前观察。
- 动作窗口内没有接触只有在相应采样完整、窗口结束并完成批次归并后才可标为空挥；采样缺失标未知，不标失败。
- 正常终局、角色死亡、任务结束、网络中止和采集截断分别标记。角色死亡结束该生命片段，不提前结束仍在进行的团队任务和整场样本。
- 小队复活选择时的资格、实际执行前的复核与最终结果分别记录；接应者随后进入交战或死亡不倒填为早先已经失效，尚未启用的能力不标成零收益或失败样本。
- 实时位姿过期与有效历史接触分开；旧生命、旧比赛、重复接触和重复上传不产生额外学习收益。

模型选了动作后若被规则拦截，须同时记录建议与实际执行动作；否则模型会把未执行动作错误归因于随后结果。真人只有可观察的已提交行为，没有内部候选评分和指挥理由时保留缺失，不补造“专家决策”。

### 数据质量与分组

本期战斗服采用客户端移动和接触事实。通过业务结构校验的数据也不是独立验证过的物理真相；训练入口应分开管理维护者验证场景、普通玩家上传与合成数据，保留来源及质量等级，不将训练清洗扩大为本期服务端物理校验。

数据整理需覆盖：

- 去重、乱序归并、版本不兼容、异常数值、缺帧和长时间停顿；异常批次隔离，避免少数来源支配训练。
- 按武将及定位、装备、难度、阵营、小队组成、局部人数、地图／模式／任务阶段与结果分层采样；保留失败、脱困、接应和防御样本，不只上传胜利或高伤害片段。
- 训练、验证、测试按整场比赛与同源采集批次分组；相邻窗口、镜像增强、重复上传及同源合成场景留在同一分组。
- 留出未见种子、装备／小队组合及对手版本的测试集；已知地图预训练后的新战况表现与未见地图／模式的泛化分别报告，不以熟悉地图成绩证明未知地图能力。资源和规则变更明确兼容边界。
- 纯电脑、真人参与和评测局分别标记。规则电脑数据适合预训练与基线复现，但不自动视为高质量专家示范。

训练规模以独立对局、交战和任务数量及覆盖度报告，不用大量相邻帧冒充独立样本。测试集不参与反复调参，历史基准保持固定，新场景另行扩充。

## 方向一 个人与局部团队作战训练

### 自监督表征与自动标签

从结构化观察序列学习装备、动作和交战关系，优先采用以下任务：

| 学习任务 | 训练目标 | 注意事项 |
| --- | --- | --- |
| 观察补全 | 从允许的历史及上下文重建被遮盖的可见字段 | 不把原本不可见的全图敌人位置当作必须恢复的答案 |
| 时序表征预测 | 根据过去观察和已执行动作预测短期状态表征 | 预测带不确定性，不替代碰撞与权威状态 |
| 攻防结果预测 | 估计有效命中、防御拦截、反弹、受击与资源变化 | 标签来自实际事件；确定的规则计算不必由模型重新学习 |
| 局部交战预测 | 估计双方交换结果、友军挡刀与多方向威胁 | 纳入队友行为及缺失信息，不只拟合单挑 |
| 协作机会预测 | 估计支援、让位、接替和侧翼机会的短期效果 | 区分相关性与动作导致的改善，后续用闭环对战检验 |
| 小队返场预测 | 机制启用后，估计接应机会持续时间、返场耗时和重新形成战斗力的效果 | 使用真实资格与复活事件；接应合法性始终由规则确定，不交给模型猜测 |

严格来说，掩码重建和时序表征学习属于自监督；由伤害、动作结果和胜负派生的目标属于自动标注监督。两者都可减少人工标注，但都不等于策略已经变强。利用未来表征预测辅助学习有研究依据，项目采用结构化战斗输入时仍需独立验证效果。[Self-Predictive Representations](https://arxiv.org/abs/2007.05929)

### 从预测走向决策

1. **规则基线学习**：以新武将策略和已接入的小队行为启动模型，检查动作语义与观察定义；旧电脑轨迹仅作为标明来源的历史样本，不要求复制其性格、索敌特权或固定策略。
2. **预测辅助策略**：模型估计命中、受击和资源风险，规则策略仍负责候选生成与动作许可；先验证预测是否改善真实决策。
3. **离线策略优化**：数据覆盖足够后，利用已有轨迹评价更好的选择，限制偏离已覆盖的动作与状态，避免对从未执行的动作给出虚高价值。
4. **闭环改进**：在单独测试对局中与固定基线、历史模型及真人反馈交叉验证，再形成下一批数据。生产对局不作为无约束探索场。

离线强化学习需要处理行为分布偏移，IQL 等研究可作为后续算法评审依据；本规划不据此选定库或承诺离线数据一定产生超越基线的策略。[Offline Reinforcement Learning with Implicit Q-Learning](https://arxiv.org/abs/2110.06169)

### 个人与团队评价目标

个人层同时评价有效进攻、自身受伤与死亡风险、防守资源管理、空挥和无效等待。局部团队层评价交战交换、队友生存、攻击通道、支援接替、重复围攻成本，以及小队机制启用后的实际返场收益与接应者缺席代价。阵营终局结果用于检验这些局部目标是否真正有益。

收益信号只来自实际、去重的战斗事件和任务结果，不以“提出攻击”“走近目标”“输出支援命令”的次数直接奖励。伤害、格挡次数和存活时长都只是辅助项，防止刷格挡、重复空挥、抢最后一击、残血无限逃跑或以友军挡刀堆动作数。

返场接应不按“持续未交战”“触发复活次数”直接奖励，避免某个成员永久躲藏或以重复死亡刷收益。应检验合法返场是否真的改善任务与后续交战，并计入接应者未参与正面战斗的代价。

武将、装备分支、主要／次要定位和熟练度作为策略条件。每名武将分别检查定位发挥、配合方式与不利对局，允许共享基础策略但不以总体胜率掩盖个别武将退化；不把旧性格标签作为训练目标。目标还包括自然节奏和可理解的对抗，而非无限提高压制强度。

## 方向二 战场调度指挥训练

### 地图模式与任务目标的离线预训练

指挥先拥有可复用的战略基础，再学习如何应对当前对局。以地图版本、模式、任务目标及阶段和战斗规则划定适用范围；不同阵营的出生位置、路线及阵容差异作为条件。维护以下产物：

| 产物 | 离线准备内容 | 局内用途 |
| --- | --- | --- |
| 地图战略知识 | 要点与连接关系、瓶颈、可选路线、基础行程、集结与撤离区域 | 直接查询候选区域和路线，不每局从零发现地图价值 |
| 模式目标与资源价值 | 胜利条件、目标依赖、阶段顺序及实际存在的关键资源价值与获取规则 | 根据当前阶段、比分、进度和资源可用性修正优先级 |
| 条件化行动预案 | 不同阵营、武将／小队组成与兵力配置下的分路、增援、转移和终局方案 | 为指挥提供任务候选、兵力范围与撤销条件，不强制照表执行 |
| 小队返场知识 | 机制启用后的候选接应区域、到达时间及与任务路线的关系 | 结合当前合法队友、地形占用和可见敌情决定是否接应；不预设某人始终未交战 |

离线流程分为五步：

1. **确认事实**：整理同版本地图结构、模式规则、任务定义与资源机制；当前死斗不存在的资源或占点目标不加入收益。
2. **计算稳定基础**：离线分析连接关系、路线成本和目标依赖，形成初始要点评价。确定事实用规则计算，不包装成必须自监督学习的未知知识。
3. **评估并预训练方案**：按阶段、阵营、阵容与典型态势构建任务场景，对候选区域、资源投入和行动预案作条件化评价；结合可用指挥轨迹学习价值与选择。抽象地图场景适合调度练习，涉及实际交战收益仍需物理执行验证。
4. **留出场景验证**：检查不同开局与动态路阻、过期敌情、人员损失、目标变更等反例，记录适用条件与不确定性，不输出脱离战况的单一固定排序。
5. **审批与发布**：把战略知识、条件化预案及其兼容版本纳入人工审批，与作战和指挥策略形成可用组合；新对局加载后整局固定版本。

没有充分玩家轨迹时，可先用规则计算与验证场景形成战略基线，之后再用集中数据改进。玩家上传仅需引用知识版本及相关决策，不承担反复上传地图资源的职责。

每局直接加载已批准知识，按本局阵营、阵容及目标阶段选用；局内处理的重点是敌情、兵力、拥堵、目标进度和返场资格等变化。阶段转换是在既定知识中切换适用方案，不是重新训练或热换模型。地图拓扑、资源机制或胜利规则变化后，对受影响产物重新评估与审批；旧知识失配时使用兼容规则策略。

### 战场表征与自监督任务

以预训练知识中的区域与通路为基础，叠加己方人员、任务关系及动态态势，不要求先构造服务端物理世界。敌情带来源、年龄与置信度，未知区域保持未知；静态重要地点不等于本局已知敌人所在地点。

| 学习任务 | 目标 |
| --- | --- |
| 战区态势预测 | 预测已知交战区域的压力、持续时间及己方兵力缺口 |
| 到达时间预测 | 比较导航预期与真实返场／支援时间，学习拥堵、局部战斗中断和路线影响 |
| 任务结果预测 | 估计任务成功、中止、过期及执行代价，学习什么增援可能已经来不及 |
| 战略价值修正 | 学习当前态势为何提高或降低离线要点评价，避免持续争夺已经失效或代价过高的目标 |
| 兵力分配表征 | 理解武将定位、装备、资源状态与小队配置的互补，而非只统计人数 |
| 小队重整预测 | 机制启用后，预测不同接应选择对返场速度、兵力恢复和原战区压力的影响 |
| 多时间尺度预测 | 预测短期支援效果与较长时间内的阵营形势，跨度随地图行程和任务长度确定 |

现有单局动作记录不足以直接提供指挥示范。先用规则指挥产生明确的命令、参与者、任务期限和执行反馈，再积累指挥训练轨迹。真人自由移动可作为事实，不通过聊天识别命令，也不把事后聚集反标成当时存在的指挥意图。

### 指挥策略优化

训练样本以任务决策至完成／中断的区间为单位，考虑不同任务的实际持续时间。候选来自适用的预训练方案及规则策略，包括继续现有任务、不增援、有限增援、集结、转移或脱离；机制启用后加入小队返场接应，以及对应模式实际存在的目标／资源任务。避免只在“向哪处派人”中选择。

指挥评价重心为阵营目标、兵力投入产出和任务完成质量：

- 增援是否在有效时间内到达，是否减少逐个投入造成的伤亡。
- 抽调人员是否使原战区出现更大损失，是否重复派出过量兵力。
- 有限集结是否改善局部交换，而不是让全队长期不参战。
- 领先、落后与临近终局时的风险取舍是否改善结果，同时保留合理交战活跃度。
- 命令是否频繁反转，局部角色是否持续拒绝不切实际的任务。
- 静态要点的价值是否被正确复用，当前敌情或目标变化是否足以触发合理改派。
- 小队接应是否加快有效返场，且没有以正面持续缺员或永久藏匿换取表面收益。

不以命令数量、移动距离或全队聚集程度作主要收益；也不把当前死斗不存在的据点控制计入胜利收益。失败任务保留局部执行原因：指挥失误、路阻、信息过期和个人战斗失败应能区分。

### 层间归因与联合演进

先固定作战策略训练和评价指挥，再固定指挥评价作战策略；双方同时变化只用于后续组合验证。对照时同时固定武将档案、战略知识和小队能力开关，避免知识或机制变化被误算为模型进步，或指挥改善掩盖个体退化。

发布前至少比较四种组合：

| 作战策略 | 指挥策略 | 检查重点 |
| --- | --- | --- |
| 规则基线 | 规则基线 | 可运行参照 |
| 候选模型 | 规则基线 | 个人与局部团队改善 |
| 规则基线 | 候选模型 | 调度改善 |
| 候选模型 | 候选模型 | 层间冲突与总体效果 |

另做战略知识消融对照：固定地图、规则、阵容与作战策略，比较不使用预训练知识、使用知识但不作动态修正、使用知识并修正三种配置，分别检查调度效果、重复计算开销和对战况变化的适应能力。该对照用于评测，不要求生产同时保留三套体系。

已有学习版本也加入对照，避免只会战胜初始规则电脑。训练对手覆盖不同武将定位、装备、小队组合和历史版本，不只与自身同一副本对打；对手池变化有记录，评测对手池保持独立。

## 当前训练环境的能力边界

[Rust 迁移回放](rust-runtime-migration.md#参考回放格式)目前用于给定输入与世界事实下的业务一致性，不是可自由推进的完整战斗模拟器。模型改变移动或攻击后，原记录中的未来位置和接触通常已不成立；把新动作插入旧回放继续计算胜率，会得到错误的策略评价。

因此分开使用三类环境：

- **历史回放**：检查数据、动作合法性、规则一致性、预测和离线策略指标，不宣称产生新策略的真实战果。
- **具备实际物理执行的测试对局**：通过原客户端运行闭环，验证候选模型改变行为后的结果；完整对战评测和当前阶段自对弈依赖这一能力。
- **后续模拟或学习世界模型**：可研究扩大训练规模，但需先验证碰撞、动作与结果误差；不作为本轮新增服务端物理的要求，也不代替真实客户端验收。

世界模型学习与策略优化是不同环节；即使能预测轨迹，也要验证策略在真实执行中的结果。相关研究将世界模型、价值评价与行动选择分开，可作为后续研究依据，而非当前工程已具备无客户端自对弈的证明。[Mastering diverse control tasks through world models](https://www.nature.com/articles/s41586-025-08744-2)

影子模式只计算候选建议、不驱动角色，适合检查兼容性、分歧、时延和合法性；因没有执行候选动作，其记录不直接证明候选模型更强。

## 评测与模型晋级

### 分层指标

| 层级 | 主要指标 | 必查反例 |
| --- | --- | --- |
| 个人 | 有效机会利用、空挥、受伤／死亡、格挡资源与盾牌利用、蓄势风险、动作合法性 | 看穿隐藏输入、机械满蓄势、永久防御、错误取消反馈 |
| 局部团队 | 局部交换、友军衰减、拥堵、支援接替、职责稳定性，以及小队机制启用后的合法返场、归队耗时与接应代价 | 队友挡刀、整队围一个人、非法跨小队复活、永久躲藏或重复死亡刷收益 |
| 指挥 | 任务完成与过期、有效增援、兵力投入、返场同步、任务反转、目标价值修正及终局表现 | 放空另一战区、无限集结、反复追逐过期敌情、盲从静态要点排序 |
| 综合对局 | 胜／平／负、比分差、交战活跃度、武将定位及阵容／小队／模式分层表现、真人体验 | 只对一个基线有效、普通难度过度压制、个别武将或罕见装备退化 |
| 工程 | 推理和队列时延、采集开销、战略知识加载与跨局复用、动态更新成本、回退率和跨平台一致性 | 上传阻塞战斗、超时拖延防御、逐局重复静态评估、地图／模式／知识版本混用 |

按固定地图、阵容、难度、成对初始种子与阵营互换比较，重复运行并报告置信区间；独立比赛才是主要统计单位。固定种子便于对照，不意味着不同策略会得到相同后续物理轨迹。

在正式比较前冻结主要指标、可接受退化范围、独立对局数量与停止条件；不足以区分差异时继续收集证据，不因一次胜利晋级。新装备及重要边缘场景单独设置通过条件，不让总体平均掩盖缺口。

### 晋级顺序

1. **数据门槛**：观察与执行可重建，版本清楚，无未来泄漏，训练与测试无同局污染。
2. **规则门槛**：候选越权被拦截且可解释，正式接受的动作无规则违规；死亡、复活、旧事件和任务释放正确。
3. **预测与影子门槛**：验证集预测及校准有效，未知情况可靠回退，候选输出及时且稳定。
4. **闭环效果门槛**：两个方向及四种组合分别验证，优于对应参照且重要场景无不可接受退化。
5. **工程门槛**：20 角色负载下满足既有战斗服时延目标，含采集和推理；不靠降低策略频率或丢弃游戏输入过关。
6. **实机与人工审批**：核对不同武将定位、武器、小队组合及地图模式的实际体验，人工批准明确的策略与战略知识组合。

全自动训练可以持续产出候选，但自动评测通过只进入待审批，不自动转为正式版本。新候选通过测试后也无需强制替换现有稳定模型。

## 发布、回退与可追溯性

每个候选关联训练数据版本、观察与动作语义、战斗／资源版本、武将策略档案、两个方向的模型、地图／模式／目标战略知识、小队能力状态、训练配置、评测报告和审批记录。模型与知识分发要校验来源与完整性，不接受上传者夹带的可执行训练内容或任意模型作为正式版本。

新对局建立时选择兼容且已批准的完整组合，资源、武将档案、模型与适用战略知识在开局前准备好；断网可使用本地兼容版本，没有兼容模型时使用规则策略，知识失配时停用相应产物，仍可离线游玩。进行中的比赛不热换权重、策略档案或知识版本，新批准版本等待后续对局。

局内推理故障可以停用该方向模型，交给既定规则策略处理，并记录回退时刻与原因；这属于故障处置，不是局内发布另一个模型。持续故障停止本局再次尝试，避免来回切换。撤回模型后停止新局采用，保留可用的上一批准版本和规则基线。

原始观察、模型建议、规则裁剪后的执行、指挥任务及随机选择均可关联，便于重放决策。跨平台推理允许按预先定义的数值容差检查，但关键场景动作选择及业务结果必须验证；遇到数值差异时不笼统承诺逐位相同，回放以记录的真实决策和事件序列定位。

## 与架构迁移并行的交付顺序

| 阶段 | 交付 | 前置条件 |
| --- | --- | --- |
| T0 语义与评价设计 | 武将定位、双方向目标、小队及复活待确认规则、地图／模式／任务知识清单、事件与评测场景 | 可以在 Rust 迁移期间完成，不依赖模型训练 |
| T1 战略基线与采集试点 | 武将／协同／指挥规则、离线地图分析与初始预案，主动开启、脱敏、有界采集和上传链路 | 地图和模式规则明确；采集依赖事件稳定及参与流程确认 |
| T2 数据集与双方向预训练 | 分组数据集、表征与预测基线，地图要点、真实资源和条件化行为预训练 | 对应场景及对局覆盖满足要求；小队复活样本仅来自已启用机制 |
| T3 作战策略候选 | 按武将与小队分别评价，预测辅助到离线优化，规则指挥与战略知识固定 | 动作覆盖、物理执行测试和影子验证可用 |
| T4 指挥策略候选 | 预训练知识结合任务级训练、动态价值修正、固定作战策略对照及多区域验收 | 有真实规则指挥轨迹，不从旧移动数据伪造命令标签 |
| T5 联合试点与发布 | 四组合及战略知识消融评测、人工审批、限定新局启用与回退演练 | 数据、规则、效果、工程及实机门槛全部通过 |
| T6 持续迭代 | 新数据覆盖薄弱场景、候选重训、历史对手池与回归集维护 | 保持审批、新局生效、版本隔离和主动参与边界 |

首轮以“记录可信、预测有用、规则始终有效”为目标，再追求对战能力提升。试点前还需冻结存储期限与容量、上传限额、评测样本量、收益权重及推理预算；这些是阶段交付条件，不在本次提前固定算法、依赖或公共 API。

地图整理、稳定价值计算与初始行为预训练可以先行，不等待大规模玩家上传。小队及周边复活按实际规则交付进度独立接入数据和训练，未启用时继续推进个人作战、已有局部协同与指挥训练。
