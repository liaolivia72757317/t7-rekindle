# Rust 战斗运行时迁移

按[目标架构](target-architecture.md)迁移现有 Python 业务，分离原客户端协议兼容、本地平台服务和跨平台 Rust 战斗核心，消除逐事件完整状态编解码和深拷贝。平台业务不并入战斗核心，Windows 客户端适配仍由启动器侧负责。

首期验证 Windows x64 启动器进程内的 1 名玩家与 19 名电脑，采用客户端采样、Rust 裁决。远端目标为 Linux 原生 Rust 宿主，与本地同源、同版本、同业务语义，但分别构建平台产物；协议兼容后续服务端运动和碰撞模拟，本期不实现该模拟。

当前只推进离线单机与 LAN 所需迁移。Java 在线平台、在线战斗节点及 Linux 远端部署后续实施；不因暂缓在线而改动共享核心、原协议或资源格式。

## 交付状态

### 产品运行时切换

按“仅移除产品运行时 Python”的范围，启动器与无界面宿主现只使用 Rust。NativeBridge 已去除 CPython 链接和业务 owner，Python 参考实现迁至 `tests/reference`，构建／导出／测试脚本保留。Debug 与 Release 都复制 Rust DLL；打包拒绝 Python 遗留文件，CI 不再下载嵌入式解释器。

默认启动的 Rust 资源准备、失败回收、连续重试，以及称号目录、查询和平台确认已接线。产品切换不代表共享房间、MatchHost、公共契约 v2／ABI 2、完整性能专项或真实双端验收完成。

本轮使用独立产物目录完成 NativeBridge、Desktop 和无界面宿主编译；Rust runtime／FFI 模块 178 项测试及 Clippy 检查通过。C++ ABI、C#→Rust→socket、称号黄金样本、默认启动失败回收与连续重试、Rust-only 无界面宿主、打包与资产复制定向测试通过。隔离包校验通过，NativeBridge 与 Rust DLL 的导入表均无 CPython 依赖。未执行项目级全量测试或切换后的真实客户端验收。


### 架构优化增量

- 已修复玩家输入时间戳在适配层丢失：战局所有者检查开局／当前生命时间下界、未来时间、倒退时间、来源和批次，失败发布不提交游标；同毫秒输入与合法迟到输入继续有效。
- 已分离轻量 `GuardMeter`，按公开字段比较状态；空接触水位不再触发全员写时复制和无效增量。防御恢复、历史清理、检查点及整批失败回滚有定向测试。
- FFI 句柄注册表不再跨输入处理或线程停止持锁；各网关独立串行化，释放后关闭句柄内对象。
- 同一 Debug 构建、20 角色／100 个空接触批次：角色复制次数与发布角色数均由 2000 降为 0；处理耗时只作本机观测，不设绝对时间断言。队列等待及完整输入负载对照仍待补齐。

剩余实施单元：公共契约 v2／ABI 2 和显式 `lifeId`；独立 `MatchHost`、多网关绑定及 Rust 唤醒式输出分发；共享 `LocalRoomService` 与 UI 无关会话编排；合成双端及其退出、背压、连续两局验收。当前尚未达到架构优化整体完成条件。

定向验证在 `src/BattleRust` 运行，`VERIFY_DIR` 指向独立产物目录：

```powershell
cargo test --locked -p t7r-battle-runtime -p t7r-battle-ffi --target-dir VERIFY_DIR
cargo clippy --locked -p t7r-battle-runtime -p t7r-battle-ffi --all-targets --target-dir VERIFY_DIR -- -D warnings
```

### 已接入模块与剩余边界

旧运行时完整战局的只读 wire 元数据还暴露了若干 `instance` 上行：原生位姿／按键报告、角色装备容器请求和已知无答复请求。Rust 网关现按原客户端格式校验并保留这些连接，不把位姿报告当作权威移动；装备容器从已绑定的本地平台配置编码。地面与地形接触现由 Rust 保留原生证据并投影命中点反馈。Python／Rust 黄金样本、战局状态测试及加密 socket 环回覆盖这些路径；由于旧记录没有原始输出字节，逐字节黄金样本来自仓库内可公开的原编解码器，而非实机输出抓包。

自动缓存由启动器侧 `ClientGateway.CreateLocalAsync` 调用进程内 Rust 预检，按冻结基线、所需原客户端资源内容和版本生成 SHA-256 身份；命中也重新检查客户端目录布局。缓存位于调用者指定的独立可写目录，写入使用文件锁和原子替换，损坏或资源变化时重建，不修改原客户端资源。C#／Rust 定向测试覆盖首次构建、命中、同大小同时间戳的内容变化、覆盖层拒绝和只读源目录。新增私有只读 `t7r_gateway_resource_json` 可从网关句柄复制同一份已校验数据包，`CreateLocalProfiledAsync` 用它初始化本地武将配置，避免托管层猜测缓存文件路径或用不同版本资源建档；尺寸探测、停止后读取和释放后拒绝均有定向测试。此入口只准备资源，不创建战局。

`BattleSession` 目前是内存中的语义化战局所有者：每次输入先复制可变状态，验证并生成有序输出，发布失败不提交；世界观测有代次与新鲜度限制，接触证据按事件时间结算并保留摆动窗口，复活需新的客户端位置样本确认。`Controller` 只产生行动和移动意图，不自行积分位置或模拟碰撞。`MotionAttempt` 必须与新鲜世界样本一致，且明确报告原生端是否尝试前移；仅连续前移而无进展时才规划脱困路径，转向和等待不会触发。原生证据已有只读采集、私有 C ABI 入口及可显式附着的原生会话接线；离网所需的地形探测仍待接线。网关 `instance` 与 WPF 显式开发路径已把受支持的语义输出转换为原客户端消息；默认生产路径已切换 Rust，Rust 开发路径已通过本页记录的单机常规功能验收，完整性能与生产关卡另行推进。

`BattleWorker` 已在独占线程运行一场 `BattleSession`：输入按事件数和估算内存有界，输出以完整事件批次入队；输出背压时拒绝本次提交，定时输出失败则结束工作线程并在停止时返回错误。100 ms AI 脉冲与动作／复活／结束期限分开唤醒，停机同步等待线程退出。定向测试覆盖无外部 `Tick` 的比赛超时、输出满时的回滚和停止后的请求失败；网关已能在私有入口持有单场工作线程并接收已绑定的世界、动作、移动尝试和接触输入，且显式开发路径已连接原生只读采样和有界客户端发送队列；默认生产路径已切换，实机时延留待性能专项。

战局成员显式区分 `Human` 与 `Bot`，并绑定非零 `sample_source_id`，不再以 RID 是否为 1 推断 AI；多名人类可分别进入复活选点、请求出生并由新位置样本确认。AI 仅对电脑成员产生决策和受击仇恨。`SourceWorld` 按来源递增批次合并位置，逐角色记录采样时刻；另一来源的新样本不会使旧角色位置重新变为新鲜。共享战局的动作、原生移动尝试、接触和出生请求均校验来源归属，旧式无来源输入只用于单来源战局。`SourceContacts` 按来源缓存证据，等所有来源的时间水位覆盖同一时刻后排序裁决，缓存有数量上限；重复批次不重放，发布失败时来源游标、待裁决证据与业务状态一同回滚。模块测试覆盖两名人类与一名电脑的同局击杀、复活、决策、归属拒绝、批次重试及水位等待。接入层仍须把已认证连接映射为来源，持续生成完整的接触时间水位并处理断线；当前不等于双客户端共享战局验收通过。

## 目标结构与约束

- `src/BattleRust/core`：比赛内强类型状态、战斗规则、语义化输入输出和导航，不调用 Windows API，不依赖原游戏报文或内存布局。
- `src/BattleRust/runtime`：战局 I/O、独占业务线程、定时器、资源及日志；兼容网关和本地平台业务与战斗核心分离。现有 Windows 原协议 codec 不作为 Linux 战斗输入接口。
- `src/BattleRust/ffi`：同一 Rust C ABI 同时构建 `staticlib` 与进程内 `cdylib`，提供版本探针、`t7r_gateway_*` 生命周期／平台邮箱及单场战局启停、kind 6／11 输入和原生移动尝试／接触批次入口。C# 启动器可直接加载动态库，NativeBridge 的内部 `BattleGatewaySink` 动态解析同一模块与句柄，避免复制一份 Rust 全局注册表；原生会话可显式附着同一句柄；WPF 显式开发模式已调用此入口，默认路径不变。
- `src/BattleRust/resources`：跨平台资源数据包加载与预检库、只读 VFS／原资源表适配，附带命令行验证入口；不启动战局、不修改客户端文件。
- NativeBridge 和 Rust FFI 当前均为 ABI 1，客户端协议不变；旧 `t7r_battle_host_*` C++／Python 接口已删除。未来 C++／Rust 边界采用固定宽度数据、明确所有权和错误码，不传递跨语言容器，不允许异常跨界。
- Windows 不增加独立 Rust 战斗进程；Linux 宿主不加载 NativeBridge 或 Python。两种接入路径共用业务校验、顺序和状态语义，本机调用不必经过 TCP；停止时等待工作线程退出后再释放资源。
- 公共协议区分玩家意图、世界观测和权威结果。权威模式绑定本次比赛，客户端采样归属和内存适配随模式确定，不按后端实现名称分支；完整契约范围见[目标架构](target-architecture.md#协议与数据契约)。
- 世界观测按版本共享；接触批次按事件时间结算。业务状态常驻 Rust，只暂存被修改部分，提交失败保持旧状态与待发送消息。
- 保留动画、输入及世界更新的因果顺序，不通过优先回复心跳、丢弃输入或降低 AI 频率美化指标。
- 在开战前完成资源读取及双方复活候选预热，战斗中只检查占用。Rust 保留原逻辑和参数，不借迁移调整战斗平衡。
- 升级或回退通过结束会话并安装完整版本生效，不迁移运行中的战局。Python 仅留作开发工具和迁移期离线参考。

## 原生只读战局采样

开发时在启动 WPF 前设置 `T7R_BATTLE_CAPTURE_PATH` 为**尚不存在的绝对 JSONL 文件路径**；父目录须已存在，且须位于客户端目录与产品包之外。例如：

```powershell
$env:T7R_BATTLE_CAPTURE_PATH = 'C:\TRACE_ROOT\capture.jsonl'
```

NativeBridge 只读取原客户端的位姿、接触日志和原生移动命令，不写入客户端程序或资源。每次启动创建新文件，已有文件不会覆盖。未设置该变量时不创建采样文件。停止时写入 `captureEnd` 并刷新；采样队列有界，接触日志丢失或写入失败会终止会话并报告采样不完整，而非静默丢弃证据。采样文件可能包含实机状态，需保留在独立开发目录，不放入仓库或产品包。

JSONL v1 首行 `captureStart` 记录 `sourceId=1`、`GetTickCount64` 时钟和本机 `clientRid` ↔ `actorId`（1–20）映射。每个 `sample` 记录比赛 `epoch`、独立递增的 `worldBatchId`、原生 `contactBatchId`、位姿／采集时间、接触时间水位、接触帧及丢失计数；角色条目含 RID、实体标识、位姿、动作状态和最后一次原生前进尝试时间；接触条目含双方 RID／实体、事件时间、扫掠比例、命中点／法线、部位、状态及速度。所有时间为本机单调运行时间毫秒，不是墙上时间；`worldBatchId` 在新 `epoch` 重新从 1 计数。`captureEnd.complete` 表示采样流无已知丢失，不代表一场比赛已完成。该格式用于冻结实机输入基线，不等同 Rust 战斗语义协议，也不构成 M0／M2 验收。

新采样的角色条目额外包含 `freshForwardAttempt`：仅当最后一次前移尝试发生在本次位姿采样之前、且相差不超过 250 ms 时为 `true`，与送入 Rust 的移动尝试判定一致。原有 `attemptedForward` 只表示历史尝试时间非零，旧 JSONL 保持可读；校验器分别统计历史尝试和新字段所标记的本次新鲜尝试，旧文件的新鲜尝试统计为 `null`，不误记为零。

现有采样文件可只读校验，不复制进仓库：`python scripts/validate_battle_capture.py CAPTURE_PATH`。工具逐行检查 JSON、来源与 RID 绑定、世界／接触批次、单调时钟、接触事件时间和移动尝试，并只输出汇总计数。武将选择或准备阶段允许 `ready=false`、接触水位停留原值；`contactsReady=false` 时采样记录只允许空接触列表，接入审计也不推进水位。接线时仅在 `contactBatchId` 增长后提交新接触批次，停滞期间不能伪造水位推进。每个可用的电脑位姿批次应向 AI 提交对应的前移尝试布尔值（包括 `false`），并校验尝试时间不晚于该位姿时间。原生运行时间须由接入层按本局时钟基准转换；采样文件本身不证明结算、回房或 Rust 处理延迟。

旧运行时的 wire 索引仍在本机时，可执行 `python scripts/validate_battle_round.py CAPTURE_PATH JOURNAL_WIRE_DIR`，只读关联完整采样时间窗与自然结算、20 人最终计分、五秒 END 保持、FINISH_GAME、退出实例、登出和回房消息的元数据顺序。已用一场自然达到击杀目标的实机记录核对：20 名角色、8,285 条接触、20 条最终计分消息，END 至 FINISH_GAME 为约 4,993 ms，随后出现登出和回房响应。该索引未采集原始报文字节，不能当作输出字节黄金样本，也不证明 Rust 客户端链路已实机通过；本地原始采样和索引均不写入仓库。

可用 `python scripts/validate_battle_capture.py CAPTURE_PATH --ingress-watermarks` 复核可用样本进入原生接入层后的批次连续性、100 ms 保守接触水位、待裁决容量及停止冲刷。以首个可用样本为时钟起点审计上述自然战局：7,793 个可用世界样本、7,107 次语义接触水位、8,285 条证据全部发布，待裁决峰值 84 条，未发现迟于已发布水位的证据。此审计不重演玩家动作、Rust 伤害裁决或客户端输出，不能替代实机 Rust 整局验收。

定向原生测试入口：`T7R.RuntimeTests.exe --battle-capture` 和 `T7R.RuntimeTests.exe --frame-hooks`。前者核对 JSONL、路径隔离、已有文件及接触丢失；后者以 x86 合成客户端核对 1–20 RID 的位姿／接触和原生移动尝试。

`BattleSnapshotIngress` 已在 NativeBridge 内作为内部转换层编译，并由 `T7R.RustBridgeTests` 通过真实 Rust 私有 C ABI 定向验证。运行中的原生 `Session` 现在可通过私有增量 `t7r_native_attach_battle`／`t7r_native_detach_battle` 附着已启动的同进程 Rust 网关战局；首个可用位姿在会话内建立原生运行时与 Rust 比赛时钟的一次性锚点。首个可用样本一次性绑定两个时钟差：动画状态时间使用原生实例相对时钟 `wireAt = matchAt + (nativeAnchor - instanceStartedAt - matchAnchor)`；伤害、击杀及计分的服务器时间使用原生运行绝对时钟 `wireServerAt = matchAt + (nativeAnchor - matchAnchor)`。两者同值重试允许，旧比赛或改值拒绝。它把原生 `instanceStartedAt`、比赛代次、来源和 RID 表用于世界样本；每个新鲜电脑位姿都提交前移尝试，超过 250 ms 的尝试按显式 `false` 处理。仅消费可用样本中增长的原生 `contactBatchId`；由于一个批次可包含多个原生帧，语义水位以**上次可用帧时间减去 100 ms 最大扫掠跨度**保守推进，后到证据先有界缓存，停止时显式冲刷最后已采集的证据。批次缺口、丢失计数及下游背压会报错并停止复用该入口。测试覆盖非恒等 RID 映射、旧原生实例、停滞水位、失败后隔离及原生会话停止／重开。当前附着、本地比赛配置、WPF 同步启停和 Rust 输出消费均已在显式开发链路接入；原有运行时仍是默认路径，定向测试不等于实机 Rust 战局验收。

托管 `ClientGateway` 现有内部比赛启停入口按 Rust 私有 ABI 1 构造 20 槽位配置，先校验成员、来源与 RID，再在同一个网关句柄上启停 `BattleWorker`。私有比赛时钟读数来自该 worker 的单调时钟，可供原生 `GetTickCount64` 采样建立本局锚点；未开局和停局后读取均失败。定向 C#／C++ 测试经真实 Rust DLL 验证未启动拒绝、无效配置不消耗代次、重复开局拒绝、同步停止、较新代次重开、时钟读数及网关停止清理；测试专用网关 DLL 未导出比赛入口时仍可运行原有大厅测试。NativeBridge 新增私有 `t7r_native_submit_start_gateway`，接收同进程网关已绑定的三个 loopback 端口，在隔离启动模式下不创建旧 `Server`；托管层有对应内部调用，定向测试覆盖无效端口、原生会话停止、失败回滚与再次启动。新增本地比赛配置工厂按原运行时的敌方优先 RID 编排、20 分钟时长和 60 次击杀目标建立 1 人＋19 电脑战局；托管层可在同一网关句柄上分阶段启动并将比赛结构传给 NativeBridge 附着入口，20 人启动／停止／重开已有定向验证。Rust 资源包中的非盾牌逐英雄、武器移动速度与冲刺参数现可经私有 `t7r_native_submit_start_gateway_profiles` 复制到 NativeBridge 启动命令，供原客户端内存覆盖层使用；旧入口及 ABI 布局不变，C#／C++ 定向测试覆盖表提取、参数校验、启动传递与失败回滚。

WPF 启动器由构建目标放置 `t7r_battle_ffi.dll`，默认使用 Rust 本地网关：同进程创建本地平台和资源缓存、预置战局、启动原客户端并附着原生采样，停止或客户端退出时按附着、客户端、战局、网关的顺序同步清理。不再保留环境变量后端开关或 Python 回退。合成客户端缺失场景已验证启动失败回滚、再次尝试且不写玩家存档。Rust logic 通道现按原业务编解码处理本地建房、入房、匹配结果和进实例通知，通知使用同进程已绑定的 instance 端口、地图及阵营；Python／Rust 黄金样本和真实 socket 测试覆盖建房／入房、延迟通知、缺失战局拒绝及较新代次重开。Rust instance 通道现按原业务编解码发送五秒后 FINISH_GAME、实例离开及延迟 SYNC_LOGOUT，并应答 USER_GROUP 退出；手动退出会裁决本局为 Quit。Python／Rust 黄金样本与 socket 环回覆盖 1 人＋19 电脑的自然结算输出、手动退出、回房消息，以及同一 logic 连接上新比赛代次的再次建局；这些均非实机整局验收。WPF 显式开发路径现按本局 SYNC_LOGOUT 加 USER_GROUP 退出或实例断开确认回房，再依次脱附原生采样、停止旧战局、从本地平台读取当前配置、预置较新代次并重新附着；Rust 私有查询／预留入口和定向测试覆盖预留后迟到的 MATCH、未回房及新局状态隔离，编译及合成启动回滚通过。大厅配置保存后，仅在匹配请求及实例绑定前、战局时钟尚未激活时，在原客户端收到成功答复前刷新预置战局；刷新先以原子预留与 MATCH／实例绑定竞争，避免跨连接检查后又启动旧战局。原生附着尚在启动时会等待附着完成，比赛已绑定的配置变更留待回房后应用。真实客户端在该路径的进图、交战、自然结算、回房和再次开局已有本页实机记录；完整表现分支、匹配前配置变更及性能专项仍待验证；生产默认路径现已切换 Rust。

已附着的原生战局即使暂时 `ready=false`，也会检查接触日志的 `droppedContacts`；发现丢失即终止会话，避免准备阶段或短暂场景空窗中的接触证据被静默忽略。原生接入层同时禁止在此类失败后复用同一比赛或冲刷待裁决的部分证据。

首轮显式 Rust 实机测试在大厅直接发起单人匹配后出现断线提示，采样仍停留在预场景 `ready=false`。对照原业务入口发现，原客户端允许未建房时直接发送匹配请求，而 Rust logic 先前要求建房或入房；放开此限制后，第二轮实机已显示匹配成功，但点击进入后再次在预场景断线。原业务还允许匹配后发起房间创建／进入请求，Rust logic 先前也拒绝此顺序；现已按原业务放开，并以加密 socket 回归覆盖直接匹配后的进入请求。第三轮实机在匹配成功后停留于战场页面，最终提示等待选择阵营回包超时；采样完整但均为 `ready=false`，未进入场景。启动器未记录网关连接错误，因此尚不能判断是 instance 连接未建立、请求未到达，还是回包未被客户端接受。

启用采样诊断时在采样文件旁创建同名 `.gateway.log`，只记录各通道连接／认证、命令编号、selector、长度和收发阶段的时间戳，不记录报文正文；日志仅用于定位进场握手，需与原生 JSONL 一起保存在独立开发目录。后续实机跟踪确认一次更早的启动断线：logic 认证后收到连续大厅请求，触发 `client receive queue full`，尚未进入匹配流程。login／logic 的收发队列现保留原容量，暂满时改为最多等待 5 秒的背压，超时仍结束连接；256 条连续加密请求的逐条有序回包、等待容量、超时回收字节预算及关闭／超限错误已通过定向测试。修复后的实机已进入大厅、完成匹配及 instance 认证；阵营选择请求连续重试且每次回包写入成功，但客户端未发送确认。对照原运行时 `Server::commit` 发现 Rust 外层 `server_time` 误用了运行时间，现统一恢复为 `0`，正文时钟不变，并用完整下行帧黄金样本及 socket 测试覆盖；此前把外层时间与正文时间相等视为正确的测试已按原封包行为修正。后续实机已收到阵营确认、选将、PLAY 和移动上行，并采到 20 角色位姿；随后原生世界提交被拒绝，触发会话清理。隔离复现定位到本机低精度 tick 与战斗服高精度时钟的锚点误差：正常样本可被映射到未来。现使用精确运行时间的保守锚点，并补充原生拒收状态码、批次和时间诊断；分辨率边界、动态 C ABI、附着／停止重开定向测试以及使用实机位姿的 3000 批隔离提交通过。战斗服时间仍是唯一裁决基准，严格未来时间检查保留；跨机来源校时尚未接通，修正后的实机整局仍待验证。

从仓库根目录启动隔离构建时，可用 `scripts/start_rust_battle_dev.ps1` 同时设置开发模式和本次独立采样路径，避免仅运行隔离构建却误入原运行时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_rust_battle_dev.ps1 `
    -StageDirectory 'C:\PROJECT_ROOT\artifacts\test-results\RUST_DEV_BUILD' `
    -CapturePath 'C:\TRACE_ROOT\capture-UNIQUE.jsonl'
```

脚本要求采样文件尚不存在、父目录已存在；可加 `-WhatIf` 只检查启动参数而不启动客户端。包含最新启动器改动的隔离构建会在日志中明确记录 `启动模式：Rust 战局`；旧隔离构建尚无该日志行。实机 Rust 战局验收须核对实际运行模式，而不能仅凭可执行文件位于隔离目录判断。

## 参考回放格式

```powershell
python scripts/battle_replay.py record --output artifacts/test-results/rust-baseline
python scripts/battle_replay.py verify --input artifacts/test-results/rust-baseline
python artifacts/test-results/rust-baseline/snapshot/scripts/battle_replay.py verify --input artifacts/test-results/rust-baseline
```

输出目录必须不存在。记录内容包括：

- `manifest.json`：schema、Python 版本、Git revision、参考源码摘要和测试范围。
- `snapshot/`：参考业务、依赖及回放工具的完整源码快照，可在后续代码改变后独立运行。
- `cases.json`：初始状态、配置、版本化世界观测，以及显式时间、连接集合、输入、定时器和接触证据。
- `expected.json`：逐事件状态、消息字节、日志、称号请求及活动定时器；浮动耗时不进入等价比较。
- `timings.json`：Python 分段耗时和离线处理耗时，不包括原生转换、排队、socket 或渲染。

JSON 使用 `{"$bytes":"00ff"}` 表示二进制；`$bytes` 是保留键，普通对象不得使用，禁止非有限数值。整数保留精确值。随机种子包含在角色初始状态中，时间由事件提供。验证报告首个差异位置，不自动更新期望结果。

当前 replay 是合成业务回放，定时器由输入明确触发；它不是原生网络调度器或完整战局模拟器。输入／世界事件的原生因果调度由独立 Rust 调度测试覆盖。后续性能回放按预定时间投递，不等待前一事件处理完成。

## 产品切换门槛

固定硬件、优化构建、20 角色负载和日志配置，三次十分钟测试均需满足：单事件处理 P95 ≤ 2 ms、P99 ≤ 5 ms；排队 P95 ≤ 5 ms；输入入队到首次发送 P95 ≤ 10 ms、P99 ≤ 20 ms；定时器实际启动迟到 P95 ≤ 5 ms；预热后的复活选点 P99 ≤ 5 ms。

同时逐项通过协议、事件顺序、失败提交、伤害与防御、接触去重、死亡复活、结算重开、存档、称号和生命周期回归。相同负载下处理 P95 至少降低 80%，正常负载不丢失输入／接触且队列不持续积压。实机操作反馈另行验收。

产品 Python 链接及业务包已按确认范围移除；manifest schemaVersion 仍为 1，运行策略字段改为 `battleRuntime=rust`，不接受旧 Python 包策略。存档、设置和订阅格式不变。完整性能及实机验收独立推进；项目级全量测试和既有产品包覆盖仍需明确授权。
