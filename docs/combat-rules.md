# 近战攻防规则

本文分开记录[当前战斗逻辑](#当前战斗逻辑)与[玩法规则](#玩法规则)，用于理解实现、核对差异和场景验收。当前逻辑以本仓库代码为准；近战按玩法规则实现；已核实的客户端数据与经确认采用的项目经验参数分别标注。远程、技能及未进入当前阵容的特性仍保留范围说明，不将项目自定公式视为原服结论。

动作同步与协议细节见[运行契约](runtime-contracts.md#模型动作)，配置与完整伤害参数见[先锋阵容与武器配置](loadouts.md)，电脑决策见[电脑玩家](computer-player.md#战斗决策)。

## 当前战斗逻辑

### 范围与数据来源

玩家与电脑共用近战动作、接触、格挡、伤害和生命结算；AI 负责选择动作，不另外决定命中或格挡成功率。当前支持四向普通攻击、徒手、已配置武器的冲刺攻击与盾牌防御，不包含远程攻击、坐骑、等级、品质、符文及强化成长的伤害结算。

- **装备**：匹配时冻结阵容与武器配置，选将、换武器和复活使用本局快照。盾牌随可用单手武器装备，双手武器与徒手不同时持盾。
- **动作参数**：[combat_profile_data.py](../tests/reference/Business/scripts/combat_profile_data.py)保存按武将／武器区分的准备、出招、收招、被招架、地形反弹、受击及冲刺参数。离线生成时优先使用实际动画有效时长，配置表兜底；运行时不重新读取客户端动作资源，也未引入动态攻速换算。
- **原始属性**：[damage_data.py](../tests/reference/Business/scripts/damage_data.py)保存零强化武器砍／刺／钝伤、独立攻防性能字母、盾牌耐久、武将护甲及特性绑定。
- **项目规则**：伤害类型的方向映射、徒手基础钝伤 `20`、蓄势峰值 `600 ms` 及伤害倍率属于当前服务端规则。原始动作伤害 ID 有保留，但其完整映射尚未核实；不把这些项目取值解释成原服性能等级或满蓄力时刻。

### 从输入到结算

```text
本局武将与装备快照
→ 客户端选向，发送攻击／防御按下或松开意图
→ 服务端检查角色状态，开始、打断或缓存动作
→ 普通攻击：准备 → 蓄势 → 松键出招 → 收招；冲刺直接出招
→ 进入出招时保存伤害上下文，开启该动作的有效接触窗口
→ 原生逐帧分别采集刀刃与身体、防御武器／盾面及场景的接触
→ 按接触发生时间结算，检查动作、生命轮次、目标与重复命中
→ 地面反馈／地形反弹／友军衰减／敌方格挡或身体命中
→ 比较性能、扣格挡值／盾牌耐久或生命，处理动作反馈、增益、死亡与计分
→ 恢复仍按住的预输入，或进入复活／回合结算
```

动作开始时保留武器与动作配置，进入 `Strike` 时再冻结基础伤害、伤害类型、攻防计算所需的攻击性能与相对重量、松键蓄势、特性和计算规则。晚到接触仍使用原出招快照与接触发生时的部位、速度、腾空和目标动作证据，不改用当前装备或投递时刻重新计算这一刀。

### 动作阶段与输入衔接

[action](../src/BattleRust/core/src/action/mod.rs)负责动作推进；下表中的“格挡”指右键持续防御。`ParryHold` 和 `parry-success` 属于普通格挡链；左键挡反独立检查攻击 `Prepare` 窗口，不把攻击 `Hold` 当作持续防御。

| 动作阶段 | 当前行为 |
| --- | --- |
| 普通攻击准备 `Prepare` | 按左键进入；提前松键只记录释放，仍完成准备后出招；仍处于 Prepare 时可挡反，接触还须位于进攻方完整 Strike 的前三分之一 |
| 普通攻击蓄势 `Hold` | 准备结束且仍按住左键时进入，无固定截止时间；从此时开始计蓄势，松键后冻结时长并出招 |
| 普通攻击出招 `Strike` | 只有配置的接触窗口内参与命中；新的普通攻防按下进入预输入，不直接取消这一阶段 |
| 普通攻击收招 `Recovery` | 无有效预输入时正常播放；出招结束已有保持中的预输入则跳过收招，进入收招后也可被新的攻防按下打断 |
| 四向格挡 | 准备固定 `0 ms`，随后进入保持状态 `223–226`；松键直接回待机，不播放防御收回动作 |
| 盾牌防御 | 准备状态 `95` → 保持 `309`；准备与成功反馈时长读取静态配置的 `guard.prepareMs`、`guard.successMs`，不套用四向格挡的零时长 |
| 冲刺攻击 | 满足客户端快跑入口与服务端状态、装备检查后，直接进入 `439`；不等待松键，不插入准备或额外收招，完整过程结束后可衔接预输入 |

`0 ms` 仍通过动作定时器推进，不等于准备、保持和成功反馈在同一事件中合并执行。准备期间松开防御会取消原定时器，直接结束防御。

输入仲裁遵循以下实现规则：

- **方向由客户端生成**：服务端接收四向意图，不重新计算鼠标方向。游戏内 `DefenseAssistMode` 复用客户端辅助选向，不代替右键按下；输入中的 `autoParry` 只校验为 `0/1`，不切换另一套命中公式。
- **右键优先**：防御按下可以取消普通攻击的准备和蓄势。攻击意图携带的 `KEY_RIGHT_MOUSE`（位 8）仍保持时忽略，不覆盖防御或其缓存；右键松开后才允许攻击取消防御。原生在“松右键、左键仍按住”时可以直接发送攻击意图，无需先收到单独的防御释放消息。
- **方向锁定**：防御准备和保持期间再收到防御按下，不重启姿态，也不缓存新防御方向；松开后重新按下才换向。
- **单槽预输入**：可缓存阶段内，最后一次有效的普通攻击或防御按下覆盖旧意图。匹配松键使其失效；恢复时仍按住才衔接，不补放已经松开的短按，不恢复被覆盖的旧输入。
- **反馈期间**：受击、被招架、地形反弹保留仍按住的预输入，也接受更新，但不提前结束反馈。格挡成功方清空原缓存；成功反馈期间右键仍按住则继续防御并锁定方向，右键松开后的攻击意图或重新按下的防御意图可缓存，但不提前结束反馈。匹配松键使该缓存失效；反馈结束只恢复仍按住的输入。
- **操作关闭**：死亡、离场、实例失效或战斗输入关闭会丢弃动作与缓存。换武器要求当前可操作且无动作或受击锁定；切换期间不接新的攻防动作。冲刺不作为预输入缓存，电脑当前不主动冲刺。

收招取消与预输入时序是项目约定；左右键优先关系与松右键的攻击意图采用已知客户端输入行为。完整窗口见[动作输入缓存](runtime-contracts.md#动作输入缓存)。

### 接触证据与先后顺序

命中由原生刀刃扫掠与身体、防御武器／盾面、场景碰撞提供证据，不以角色相距多少米或是否处于攻击扇形内直接扣血。刀刃使用实际刀光绑定端点，关闭刀光显示不关闭检测；徒手使用右手挂点短段近似。扫掠是相邻帧间的分段线性近似，不是精确体积扫掠或历史身体姿态回放。

[contact_journal.py](../tests/reference/Business/scripts/contact_journal.py)按以下规则消费原生接触：

1. 仅接受本局、对应实体和生命轮次的有效记录；按出招序号、状态匹配攻击快照。
2. 接触必须处于 `phaseAt + contactStartMs` 至 `phaseAt + contactEndMs` 之间，含两端。`phaseAt` 是原生实际出招起点，不是主机首次观察或业务投递时间。普通攻击资源的 `0/0` 窗口解释为完整出招阶段；显式窗口超过动画时长时截到动画结束。
3. 同批接触按 `occurredAt → along → actorId → targetId` 排序，即发生时间、刀根到刀尖位置和角色 RID；完全同一时刻、同一刀刃位置、同一目标的武器与身体接触以武器优先。武器与身体分槽保留，先碰身体就直接命中。每批只消费一次，每刀对同一敌人最多扣血一次，对同一友军身体最多记一次衰减。
4. 正常进入收招或下一动作，不丢弃已经发生的有效接触；动作被打断后只保留中断时刻及之前的接触。复活或新实例不继承上一生命／战局的命中记录。
5. 缺失、非法或未就绪的几何不回退到距离命中。实时位姿的 `250 ms` 新鲜度限制不用于否定队列中仍与原动作匹配的历史接触。

同一挥击中的结果按先后顺序累积：

| 接触对象 | 当前处理 |
| --- | --- |
| 地面／坡面 | 每刀最多一次材质音效，不取消攻击窗口，不阻止后续身体接触 |
| 墙壁、陡面、障碍物侧面或头顶障碍 | 立即停止这一刀，进入对应方向地形反弹；此前已结算伤害保留，后续接触停止 |
| 友军 | 身体接触不扣血、每名仅记一次衰减；友军武器接触忽略。两者均不消耗敌人穿透名额 |
| 敌方格挡盒／盾面 | 有效普通格挡或挡反先比较性能；挡住则停止这一刀。盒体破防等待真正身体接触再结算一次减伤，仍可继续顺劈；盾面保留原有结算 |
| 敌方身体命中 | 扣血并占用一个敌人穿透名额；仍有名额和有效窗口时可继续命中其他敌人 |

地面判定同时要求单位法线的 `abs(normal.z) >= 0.5`，且接触平面投影到攻击者脚下 XY 的高度不超过脚底 `0.1 m`。法线翻转不改变这一分类；头顶平面不作为可穿过的地面。具体实现见 [blade_contacts.py](../tests/reference/Business/scripts/blade_contacts.py)。

### 武器拦截、挡反与盾牌

普通主手采用角色正面的查询用格挡盒，提前拦截攻击扫掠，不再要求两把武器的可见刀刃相交。该盒不注册为 Havok 刚体，不参与移动、推挤或导航，也不宣称还原原服防御实体。原始几何来源的证据边界见[防御几何来源核实](planning/guard-geometry-investigation.md)。

盒体全尺寸为宽 `1.2 m`、高 `1.8 m`、深 `0.3 m`，中心在角色位置向前 `0.65 m`、向上 `1.05 m`；水平前向为 `(cos(yaw), -sin(yaw), 0)`。盒体随角色位置和朝向更新，不随武器动画摆动。主手一律使用此查询，取代主手原生根形状与刀刃胶囊回退；盾牌仍只查询实际副手的原生形状。不分配 `20002`／`20006` 等代理资源，`defenceWeaponId` 保持实际装备 ID。

游戏线程用攻击者同一套刀刃扫掠查询当前帧盒体，只接受同一物理世界中存活、装备激活、处于有效防御阶段的目标；不依赖防守武器刀刃端点。防御在帧间开始时，时间扫掠裁剪至启用时刻，不补算启用前的接触。释放、受击、换武器及非防御阶段不沿用旧盒体。

格挡体、身体、盾牌与场景接触分别保留，按首次接触时间及刀刃位置排序；同点防御优先。格挡体证据标记 `GuardVolume`、`region=0`、`bodyIndex=-1`。无效防御直接忽略，保留之后的身体候选，不把盒体接触伪装成身体命中。实现见 [WeaponGuardHookCode.cpp](../src/Runtime/launcher/WeaponGuardHookCode.cpp) 和 [contacts.rs](../src/BattleRust/runtime/src/battle_session/contacts.rs)。

- **普通格挡**：保持状态 `223–226` 及成功反馈 `231–234`，在盒体接触成立后检查方向：上劈只接受上防，下刺只接受下防，左右横击接受左防或右防（16 种配对中的 6 种）。无接触或身体先碰仍受伤；不额外增加正面角度门槛。冲刺沿用原方向策略，盾牌 `309`／`111` 不套用此四向过滤。
- **挡反**：防守方仅攻击 Prepare 状态 `235/241/247/253`，同时接触须落在进攻方完整 Strike 时长的前三分之一（含边界）；时长取本次动作配置，起点取攻击接触的原生 `phaseAtMs`，不使用消息到达时间或防守方起手后 `50–200 ms`。上起手接上／下攻击，左右起手接镜像横砍，下起手接下刺；Hold、Strike 不生效。成功只招架进攻方，防守方继续原攻击准备。
- **盒体性能破防**：首次只播放一次碰撞反馈，记录这一刀对该目标实体／生命代次的减伤比例，不扣血、不使其受击、不停止挥击。之后同批或跨批真正接触身体时，按该身体接触的部位、时间和运动信息结算一次减伤命中；没有身体命中就没有伤害。停止、过期攻击及旧生命证据不再使用该记录，发布失败整体回滚。原生盾面及旧版本武器证据仍保留原结算语义。训练评分使用明确的格挡／挡反／破防结果，不以同批是否扣血倒推成功。
- **历史接触**：依据接触时的目标状态、起点和武器判定；释放或打断时记录截止时间。之前的有效拦截仍结算资源及声音，但不让已经松键、转入其他动作的防守方重新举起武器。
- **普通反馈**：攻击者按本武器被招架时长恢复。四向防守成功基础反馈 `0 ms`；盾牌保留静态 `successMs`。攻击性能高一级时，成功反馈至少 `250 ms`，不能提前攻击；再次格挡不缩短已有硬直的剩余时间，右键仍保持则结束后继续防御。

普通格挡比较攻击性能与防御性能；挡反比较双方攻击性能。性能差、格挡消耗与受击参数统一见下节。所有 B 级属性使用通用规则，没有单独例外。

盾牌正常挡住攻击后另扣自身耐久，不应用角色护甲和部位倍率；绑定破盾特性时耐久损耗另乘 `1.5`。打碎盾牌的一击仍全部吸收、不溢出，播放状态 `41`、持续 `1000 ms`，本条生命禁用副手；换武器不修复，重新出战恢复。性能直接破防不算耐久耗尽，不重复扣格挡值或盾牌耐久。

### 格挡与受击参数来源

性能与资源公式见 [guard.rs](../src/BattleRust/core/src/guard.rs)，生产接触判定见 [contacts.rs](../src/BattleRust/runtime/src/battle_session/contacts.rs)。历史 Python 对照和核心旧挡反窗口函数保留其语义，不作为当前生产窗口。

| 参数 | 当前值 | 来源 |
| --- | --- | --- |
| 攻防性能 | `SS > S > A > B > C > D > E > F`，分别读取攻击／防御字母 | `s_weapon_attr` 的 `dis_attack_power`、`dis_defence_ability`；空白按项目 F 兜底 |
| 格挡值初始／上限 | `5` | `s_battle_common_para_cli` 参数 91 |
| 格挡后恢复等待／每秒恢复 | `2500 ms`／`2` | 原始参数 93、94 |
| 主动近战命中或被挡恢复 | `2`，不超过上限 | 原始参数 95 |
| 耗尽后立即重置 | `2` | 原始参数 97 |
| 单击格挡消耗 | `clamp(1 + 0.25 × 性能差 + 0.5 × (攻击重量 / 防御重量 - 1), 0.25, 2.5)` | 经确认采用的项目经验公式；挡反的性能差按双方攻击性能计算 |
| 普通格挡保留伤害 | 性能差 `≤1` 为 `0`；差 `2/3/≥4` 为 `25%/50%/75%` | 项目经验值；在伤害最终取整前相乘 |
| 挡反被击破 | 性能差 `≥4`；差 `4/5/≥6` 保留 `25%/50%/75%` | 通用性能门槛；伤害系数为项目经验值 |
| 高一级格挡硬直 | 至少 `250 ms` | 项目经验值，保留更长的盾牌成功反馈 |
| 格挡值耗尽硬直 | `1000 ms`，状态 `598` | 原生疲劳破防状态；持续时间为项目经验值 |
| 挡反窗口／满蓄力 | 防守方 Prepare，且接触在进攻方完整 Strike 前 `1/3`／Hold 满 `600 ms` | 项目规则；Strike 时长取动作配置 |
| B 级以上命中轻／中甲的移动锁定 | `250/180 ms` | 项目经验值；动作受击恢复仍用武器配置 |
| B 级以上命中腾空目标 | 击倒 `1000 ms`，状态 `40`（性能破防为 `362`） | 原生状态；触发条件和时间为项目经验值 |

原始资源的重量显示字段缺少可用数值，暂以已绑定的徒手／轻／中／重／超重（含重盾）移动重量分类映射相对权重 `0.5/1/1.5/2/2.5`，未分类为 `1`；这些是项目权重，不是原始公斤数。护甲类型暂按原始数值护甲 `≤55`、`56–75`、`>75` 映射轻／中／重甲，也属于项目分类。两项集中在 [damage_resources.py](../tests/reference/Business/scripts/damage_resources.py)，分别标记 `weightSource`、`armorTypeSource`。

有效格挡（含挡反）才扣格挡值；性能直接破防不扣。恢复按原生接触水位推进，不按投递延迟额外回血；挥空、碰墙和碰友军不触发主动恢复。恢复值通过原 `BATTLE / PARRY_VALUE_NOTIFY`（selector `48`，单个 float）发给本地 HUD。格挡值耗尽的一击仍挡住，随后长硬直并重置；生命、格挡值和盾牌耐久是独立资源。

### 身体伤害、蓄势与特性

玩家与电脑的初始生命和复活生命均取所选武将的原始 `s_hero_attr.max_hp`，不固定为 `100`；字段来源及范围见[生命属性说明](loadouts.md#近战伤害)。血量同步使用实际数值，逆境特性和 AI 低血量判断使用当前生命／该武将生命上限。对已通过接触、阵营、防御和穿透检查的身体命中，[damage_rules.py](../tests/reference/Business/scripts/damage_rules.py)计算：

```text
原始伤害 = 基础伤害 × 护甲倍率 × 部位倍率 × 蓄势倍率 × 挥击阶段倍率
         × 相对速度倍率 × 特性与增益倍率 × 友军衰减 × 敌人穿透倍率 × 破防保留比例
实际扣血 = min(目标剩余生命, max(1, floor(原始伤害 + 0.5)))
```

未命中、成功格挡、友军自身及穿透名额耗尽均不进入上述最低 `1` 点扣血逻辑。当前允许自然一击致死，普通攻击和冲刺不再分别固定为 `20/40` 点伤害。

| 因子 | 当前规则 |
| --- | --- |
| 基础伤害与类型 | 下方向优先刺、其次钝与砍；其余方向及冲刺优先砍、其次钝与刺，只选择武器原属性中的正值；徒手为项目基础钝伤 `20` |
| 护甲 | `100 / (100 + armor × K)`，砍／刺／钝的 `K` 分别为 `1 / 0.6 / 0.35`；减伤与前述项目护甲类型的受击门槛分别处理 |
| 部位 | 头 `1.5`、躯干 `1`、腿 `0.75`；从原生骨骼刚体识别，未知部位按躯干并记录诊断，不按接触高度猜测，也无随机暴击 |
| 蓄势 | 进入 `Hold` 后计时，松键冻结；`0 ms → 1`、`600 ms → 1.5`、`1000 ms → 1.1`，中间线性插值，之后维持 `1.1`；提前松键与冲刺按 `0 ms` |
| 挥击阶段 | 接触时刻在有效窗口中归一化；窗口两端为 `0.25`，`35%–65%` 为 `1`，中间线性变化 |
| 相对速度 | 沿武器相对攻击者的运动方向计算双方平移的影响，倍率限制在 `0.5–1.5`；采样不连续或基准速率低于 `0.1 m/s` 时为 `1` |
| 友军衰减 | 此前擦过 `0 / 1 / 至少 2` 名友军时为 `1 / 0.4 / 0.05`；衰减命中显示黄色伤害，攻击性能降为 F；是否打断仍看护甲类型 |
| 敌人穿透 | 顺劈无／低／中／高依次为 `[1]`、`[1, .5]`、`[1, .65, .4]`、`[1, .8, .6, .4]`；既限制可伤害的敌人数，也修正后续伤害 |

原客户端的部位提示与飘字读取 `BATTLE_RESULT.target_rb_index`，该字段实际消费 `COLLISION_PART`：无部位 `0`、头 `1`、躯干 `2`、腿 `3`。下发值必须来自结算部位；原始刚体 `bodyIndex` 仅保留在接触证据中，不直接用于提示，也不以 `IS_CRITICAL` 代替部位字段。

特性只对实际绑定的武将或武器生效。当前接入轻盈、反制、蓄力精通、势大力沉、逆境、刺客、破盾与顺劈，以及事件触发的反击、连击、狂怒；未接入的原始特性只保存 ID，不默认启用。反制仅在长柄下方向攻击命中正在 Strike 的目标时伤害 `×1.2`、攻击性能 `+1`，不把 Prepare／Hold 当作正在挥击。满蓄力的势大力沉按绑定等级和方向修正攻击性能，最高 SS；普通蓄势与蓄力精通继续影响伤害，不额外猜测性能加成。

成功格挡、有效命中、击杀分别触发已绑定的反击、连击、狂怒增益：前两者 `×1.2` 持续 `3 s`，后者 `×1.2` 持续 `5 s`。同名刷新不叠层，不同增益相乘；只作用于之后进入出招的攻击，不回加到触发它的这一刀。有效期按接触发生时间判断；延迟事件可补正之后已建立的攻击快照。详细特性倍率与速度公式见[近战伤害](loadouts.md#近战伤害)，快照处理见 [damage_state.py](../tests/reference/Business/scripts/damage_state.py)。

### 受击、死亡与回合结束

- **动作打断**：F 性能命中重甲不取消攻防；其他当前近战身体命中进入受击 `35`。已配置先锋通常为 `550 ms`，未使用先锋动作配置的默认电脑为 `400 ms`；保留仍按住的预输入，连续受击不会缩短原有锁定。
- **移动与击倒**：B 及以上按上表区分轻／中甲移动锁定与重甲；真实目标腾空证据可触发击倒，不用攻击者腾空代替。移动锁定与动作恢复独立计时，玩家经原移动开关通知暂停／恢复，电脑在锁定期间停止位移。楼梯／坡地后退不凭位置猜测“不稳定”，目前只有实际腾空触发该击倒。
- **免疫边界**：判定函数把移动／击倒免疫与动作打断阈值分开；当前先锋阵容没有力士技能或喝药增益入口，不为未绑定角色自动添加免疫。远程与技能击倒仍不在本次近战范围内。
- **死亡与计分**：生命归零后取消动作与旧定时器，每次死亡只登记一次；击杀者击杀数 `+1`、战场积分 `+100`，死者死亡数 `+1` 并清空本条生命的连杀。普通非致死命中不计分，阵营比分汇总累计击杀，不使用积分或连杀数。
- **复活**：电脑死亡后等待 `5 s` 再尝试本阵营复活；玩家等待 `8 s` 进入选将流程，确认出战并满足复活条件后重建角色，而非到时自动满血。复活恢复生命、格挡值、所选装备与盾牌耐久，清空伤害增益、移动锁定和旧接触；累计击杀、死亡与积分保留。
- **回合**：新局默认时限 `20 min`、阵营击败目标 `60`，开局固定本局值。达标或到时后停止后续命中与复活；到时比较阵营累计击杀，相同则平局。每次个人死亡不直接结束回合。

生命与结算入口为 [player_life.py](../tests/reference/Business/scripts/player_life.py)、[bot_life.py](../tests/reference/Business/scripts/bot_life.py)、[scene.py](../tests/reference/Business/scripts/scene.py) 和 [settlement.py](../tests/reference/Business/scripts/settlement.py)。

### 战局小队与队友附近复活

- 在原生战局小队面板创建、加入或退出小队；队长可解散、锁定或开放小队。小队仅容纳同阵营成员，每队最多 `5` 人；队长退出后由最早加入的剩余成员接任，空队自动移除。成员关系跨死亡保留，新战局重新建立。
- 电脑在开局按阵营与角色编号自动组队，每队最多先分配 `4` 名电脑。当前真人玩家自动加入本阵营第一小队，其余电脑小队至少保留 `1` 个空位；真人可退出后加入其他小队或自行建队。
- 玩家死亡后仍须等待 `8 s` 并选将，再选择同小队的存活成员作为复活参照。沿用原客户端受击冷却规则：目标最近 `10 s` 内未受到有效敌方命中或招架接触；仅攻击、空挥、友军或无效接触不刷新该冷却。
- 客户端提交目标队友和复活位置，服务端在实际执行时重新检查成员关系、生命与最新位姿、冷却、水平距离 `5～10 m`、高差不超过 `1 m`、地面可达性和角色占用。目标已死亡、换队、移动至请求范围外或位姿过期时返回原生错误提示，保留选将状态，允许重选队友或使用普通复活点。
- 小队复活复用普通复活的生命、格挡值、装备与盾牌恢复，并继续等待新生命位姿确认；不缩短死亡等待时间，不隐式退回普通复活点。电脑仍沿用本阵营常规复活流程。

小队与复活权威入口位于 [squads.rs](../src/BattleRust/runtime/src/battle_session/squads.rs) 和 [squad_spawn.rs](../src/BattleRust/runtime/src/battle_session/squad_spawn.rs)；原生协议使用 `0x40` 小队消息及 `0x36/100` 的 `type=3` 队友附近复活请求。

## 玩法规则

以下保留玩法层的操作与机制说明。右键格挡、左键起手挡反、性能压制破格挡、格挡值耗尽和盾牌破损是不同机制；本项目的近战参数采用前述已确认取值；远程、技能与原服精确参数的待核实部分不视为已接入功能。

### 防御类型与术语

| 类型 | 输入与作用 | 装备条件 |
| --- | --- | --- |
| 盾牌防御 | 通过右键举盾防御 | 持有可用盾牌 |
| 四向格挡 | 通过右键维持上、下、左、右之一的防御姿态 | 大部分不持盾的近战武器 |
| 四向挡反 | 通过左键攻击起手，在短暂阶段内弹开来袭武器 | 支持挡反的近战武器 |
| 无普通武器格挡能力 | 不具备上述右键武器格挡能力 | 长弓、银针、香炉等特殊装备 |

防御能力应按实际装备区分，不默认所有武器都支持同一种防御。格挡是持续防御，挡反是攻击起手中的防御窗口；格挡结束后发起的攻击称为还击，不与挡反混用。

### 输入与动作

#### 方向选择与锁定

手动四向格挡采用以下操作顺序：

1. 观察对手的举武器姿态和攻击起手，判断来袭方向。
2. 向所需方向移动鼠标。
3. 在移动过程中按住右键，进入对应的格挡姿态。
4. 确认格挡成功或威胁解除后，松开右键。

方向选择遵循以下行为：

- 按下右键时，根据此前紧邻的鼠标运动方向选向；当前没有移动时，沿用最后一次移动方向。
- 右键保持期间，四向格挡姿态锁定。继续移动鼠标或转动镜头不会重新选择姿态。
- 换向必须先松开右键，再向新方向移动鼠标并重新按住右键。
- 鼠标移动幅度可以很小，关键是方向准确和输入顺序正确；斜向移动容易选择到非预期方向。
- 正鼠与反鼠等输入设置会影响方向映射，操作与判定应区分玩家配置，不硬编码一种映射。

#### 状态限制与输入优先级

- 持续按住右键可以维持格挡，同一姿态可连续拦截其覆盖方向的攻击，不因成功一次就自动结束。
- 维持格挡以角色状态未被打断为前提，受击、倒地等状态需要单独处理。
- 武器正在挥击、角色正在受击或被撞倒等阶段，防御输入不等于立即进入格挡；输入是否缓存与何时衔接属于动作状态逻辑。
- 在角色状态允许时，左右键同时按住以格挡为优先；先按左键还是先按右键不改变这一优先关系。
- 举武器准备攻击时，可以通过右键转入格挡；这一行为不代表所有出招阶段均可立即取消。

#### 攻击与格挡后还击

按下左键使角色举起武器、准备攻击，松开左键发出攻击。快速点击左键仍然经过准备过程，不直接跳到命中。

| 阶段 | 仅按右键格挡 | 保持左键进行格挡 |
| --- | --- | --- |
| 准备防御 | 按住右键 | 左键保持按住，同时按住右键 |
| 等待攻击 | 保持格挡，确认拦截成功 | 保持格挡，确认拦截成功 |
| 结束防御 | 松开右键 | 松开右键，左键仍保持，进入举武器状态 |
| 准备还击 | 再按下左键举起武器 | 无需再次按下左键 |
| 发出还击 | 松开左键 | 松开左键 |

保持左键的方式减少一次重新按键操作，有利于衔接还击，但不省略武器准备动作，也不保证还击先于对手命中。是否继续防御或释放攻击，仍取决于双方动作和命中时机。

### 接触与方向判定

格挡不是全身免伤状态。当前主手由正面盒体拦截，盾牌由真实盾面拦截；实际攻击轨迹、双方位置和朝向决定是否接触。

- 攻击武器先接触有效格挡盒或盾面，再进入方向与攻防性能结算。
- 攻击绕过格挡盒／盾面、先接触身体，则按身体命中处理；仅持有格挡姿态不足以免伤。
- 应正面朝向来袭者；侧后方攻击若绕过防御武器，仍会命中身体。
- **错位格挡**：左右横击均可用左防或右防，但仍需实际碰到正面盒体；枚举配对不替代几何判定。
- 持续同向格挡可以应对连续同向来袭；单一姿态不保证同时防住多方向夹击。

方向描述需要区分攻击者自身方向、防守者自身方向和屏幕观察到的来向，不直接比较双方本地的左右名称。保持同一格挡姿态与保持同一世界朝向也不是一回事。

### 挡反与压刀

#### 挡反的有效阶段

挡反发生在左键攻击起手、武器正在举起的短暂阶段。武器已经举起并保持不动后，不再持续具有挡反效果；单纯长按左键不等于持续防御。

挡反需要对应来袭方向，上方向起手可挡反上、下方向攻击。当前方向配对与进攻方 Strike 前三分之一窗口见前述项目参数；它们不等于已还原原服生效帧。挡反需真实扫掠接触项目格挡盒，不依赖主手原生碰撞体，也不只凭姿态免伤。

#### 压刀与防御时机

压刀通过延迟出手或实际命中时间，改变防守者预判的节奏：

```text
显示攻击起手
→ 防守者短按右键并提前解除防御，或提前触发挡反
→ 攻击延迟到防御状态或挡反窗口结束之后
→ 命中防守者
```

持续格挡可以等待实际接触，比固定点按一次更能应对延迟攻击。结束防御应结合成功格挡的动作、碰撞声或威胁解除情况，而不是仅依据对手出现攻击起手。

持续防御与快速还击存在时机取舍。练习目标是准确识别威胁何时结束，再缩短多余的防御时间，不是固定维持某个时长。

### 攻防性能与结算

#### 性能等级与属性边界

| 属性 | 作用 |
| --- | --- |
| 攻击性能 | 决定攻击的压制能力，包括破格挡、动作打断和部分受击反应 |
| 防御性能 | 决定武器或盾牌承受攻击时的表现 |
| 格挡值 | 成功格挡时消耗、间隔恢复或主动进攻可以恢复的防守资源 |
| 护甲类型 | 影响身体命中后的动作打断、移动受限等反应 |

攻击性能不等于单次伤害，防御性能不等于角色护甲，格挡值也不等于盾牌耐久。已知性能等级从高到低排列如下；等级差按此顺序计算，不代表客户端内部枚举值：

```text
SS > S > A > B > C > D > E > F
```

武器的攻击性能和防御性能分别读取，不默认二者相同。例如，匕首为 E 级攻击、F 级防御，长矛为 C 级攻击、D 级防御，戟为 C 级攻击、C 级防御。

| 盾牌类型 | 防御性能 |
| --- | --- |
| 重盾 | A |
| 中盾 | B |
| 轻盾 | C |
| 格斗盾 | 按当前原始表字母；不应用历史描述中的 D→C 隐式替换 |

#### 普通格挡的性能判定

普通格挡比较进攻武器的本次攻击性能与防守武器或盾牌的防御性能。形成有效格挡接触后，所有等级（含 B）使用以下通用规则：

| 攻击性能与防御性能 | 行为结果 |
| --- | --- |
| 同级或攻击性能更低，例如 C 对 C | 正常格挡，不因性能差额外产生格挡硬直；角色状态允许时可以衔接还击 |
| 攻击性能高一级，例如 C 对 D | 挡住攻击，但防守者产生短暂格挡硬直，期间攻击、防御操作受限 |
| 攻击性能高两级及以上，例如 D 对 F、B 对 D | 直接破格挡，防守者仍受伤，但保留减伤收益 |

正常格挡、格挡硬直、直接破格挡受伤和绕过格挡直接命中应分别处理。直接破格挡不等于无防御命中：性能差距越大，破格挡后的伤害通常越高；蓄力还会改变攻击伤害，当前保留比例采用前述项目经验值，不把它解释为原服公式。

直接破格挡不要求先打空格挡值，也不与盾牌耐久耗尽的破盾混为一类。

#### 蓄力与势大力沉

势大力沉按本次攻击的方向和满蓄力条件提升攻击性能，不是常驻面板加成：

| 特性 | 满蓄力上劈 | 满蓄力左右横砍 |
| --- | --- | --- |
| 低级势大力沉 | 提升 1 级 | 项目规则：不提升 |
| 中级势大力沉 | 提升 2 级 | 项目规则：不提升 |
| 高级势大力沉 | 提升 3 级 | 项目规则：不提升 |
| 特级势大力沉 | 提升 3 级 | 提升 1 级 |

例如，基础攻击性能为 B 的武器，中级势大力沉上劈满蓄力后为 S，高级或特级势大力沉上劈满蓄力后为 SS；特级势大力沉左右横砍满蓄力后为 A。

性能判定应使用本次攻击满足条件后的等级。当前满蓄力为 Hold 满 `600 ms`；同类势大力沉仅取最高绑定等级，然后叠加满足条件的反制，最高 SS。下刺和冲刺无额外势大力沉加成，低／中／高级横砍无额外加成。这些未核实项采用项目规则，不回推原服数值。

#### 挡反的性能判定

挡反比较双方武器的攻击性能，而不是进攻方攻击性能与防守方防御性能。满足挡反动作窗口、方向和接触条件后：

- 进攻方攻击性能高出挡反武器攻击性能 3 级以内时，性能差本身不击破挡反。
- 高出 4 级及以上时，挡反被击破。
- 例如，C 级攻击性能的戟可以挡反 S 级攻击，二者相差 3 级。

挡反使用的比较属性与普通格挡不同，不实现为简单的“防御性能增加两级”。

#### B 级统一规则

B 级没有特殊例外：A 对 B 普通格挡是短硬直，B 对 B 是正常格挡；用 B 攻击性能挡反时仍需对方高出至少 4 级才击破。格斗盾也按当前资源导出的防御字母计算，不隐藏替换等级。

### 格挡值与持续防御

#### 消耗、恢复与耗尽

- 成功格挡会消耗格挡值，削减量与双方武器重量差、攻击性能和防御性能的关系有关。攻击性能低于防御性能时，格挡值削减较少。
- 原本就直接破格挡的攻击不再削减格挡值，不与正常格挡消耗重复结算。
- 一段时间未再格挡来袭攻击，格挡值会恢复。
- 自己的近战攻击命中敌人，或者被敌人格挡，也会恢复自己的格挡值；单纯挥空不属于这两种恢复条件。
- 格挡值耗尽后，防守者进入明显的长硬直，给对方追加攻击的机会，并触发格挡值重置。
- 这套机制同时适用于自动格挡和手动格挡。成功格挡后，格挡值在屏幕下方以半透明形式显示。

两种破防路径应分别记录：

```text
性能压制：等级差满足直接破格挡条件 → 结算破格挡伤害
资源耗尽：连续成功格挡 → 格挡值归零 → 长硬直与格挡值重置
```

主动还击即使被对方挡住，也有恢复自身格挡值的收益。持续承受攻击而不还手更容易被打空格挡值，不将“连续格挡若干次”实现为忽略恢复行为的固定次数计数器。

#### 连续格挡次数参考

按当前经验公式，双方相对重量相同、期间没有自然恢复或主动恢复时：同性能每次消耗 `1`，第 `5` 次耗尽；攻击高一级每次 `1.25`，第 `4` 次耗尽；低一级每次 `0.75`，第 `7` 次耗尽。高两级以上直接走性能破防，不再通过固定次数耗尽。不同重量、攻击间隔或主动还击会改变次数。

### 身体命中与受击反应

动作打断、格挡硬直、移动受限、击退和击倒是不同效果，应分别处理。护甲类型影响身体命中的反应，不替代武器防御性能。

| 条件 | 受击反应 |
| --- | --- |
| B 级及以上攻击命中轻甲或中甲 | 出现短暂的移动受限硬直 |
| 同类攻击命中重甲 | 不出现上述普通移动受限硬直，但攻击、防御动作仍可能被打断 |
| B 级及以上攻击命中腾空或站立不稳定的目标 | 可能击倒，例如跳跃时或在楼梯、坡地上后退时受击 |
| F 级或更低攻击性能命中重甲 | 不打断其攻击、防御动作 |

近战攻击先碰到队友、再碰到敌人时，后续命中的攻击性能为 F 或更低，伤害数字呈黄色。该弱化命中应与未受阻的命中区分。

以下技能交互也会造成击倒，目标具有免疫特性时另行处理：

- `F`、`E` 技能命中正在持远程武器作攻击姿势的目标，可以将其击倒。
- `F` 技能命中腾空目标，可以将其击倒。

此处 `F`、`E` 是技能按键，不是性能等级。

### 武将特性与增益

| 特性或状态 | 触发条件 | 行为 |
| --- | --- | --- |
| 神射·长弓的爆头特性 | 满弓命中头部 | 包括重甲在内的目标出现移动受限硬直 |
| 神射·长弓的爆头特性 | 未满弓命中头部 | 仍可打断目标攻击、防御动作，与满弓的移动受限效果区分 |
| 轻装近卫「反制心得」 | 下方向攻击命中正在挥动武器的敌人 | 本次攻击性能提升 1 级；提升至 B 后可使轻甲、中甲出现移动受限硬直 |
| 力士「攻城拔寨」 | 特性生效 | 免疫击退、击倒及上述命中引发的移动受限硬直 |
| 力士喝药后的增益 | 增益持续期间受击 | B 级及以上攻击性能可以打断其攻击、防御动作，C 级及以下不触发该打断 |

免疫击退、击倒或移动受限不等于免伤，也不等于攻击、防御动作始终不受打断。动作打断阈值与位移类免疫应独立判断。

### 远程攻击的打断规则

- 弓类武器在准星尚未完全收拢时射出，通常不打断目标动作；命中头部触发武将特性时另行判定。
- 飞斧、飞戟、短弓等 E 级远程攻击随距离增加会失去动作打断能力，距离阈值随目标护甲类型变化。
- 上述 E 级远程攻击命中头部仍可触发动作打断；动作打断与长弓特性的移动受限效果分别处理，并核对目标的免疫或增益状态。

距离衰减应与性能等级、护甲类型、命中部位和武将特性一起判定，具体距离阈值尚未确定。

### 练习与生存收益

#### 练习方式

- **实战练习**：识别来向、主动使用格挡，在攻击与防御之间切换，逐步减少失误。
- **打铁**：两人交替攻击、格挡和还击，先放慢速度保证输入准确，再逐步加入假动作、变招、压刀等变化。
- **夜叉舞**：绕木桩或固定目标移动，保持目标位于屏幕中央，同时循环切换格挡方向。可先原地练习“上下上下左、上下上下右”，熟练后加入左右绕行。
- **高级防御训练**：限时应对电脑攻击，格挡与还击增加分数，时间结束后结算。

练习顺序以准确为先，再缩小鼠标移动幅度、缩短按键间隔并加入走位。稳定格挡与挡反可以同时掌握，前者不依赖短暂挡反窗口。

#### 成功率的含义

格挡成功率是操作表现的统计，不是角色随机触发格挡的概率。训练提高的是方向判断、输入精度和时机控制，不意味着每次攻击都能被防住。

在每次攻击独立、格挡成功率恒为 `p`、成功格挡完全免伤、未格挡的三次等额命中致死且无恢复等额外因素的理想模型下，平均承受的攻击次数为 `3 / (1 - p)`，其中 `0 <= p < 1`：

| 格挡成功率 | 平均承受攻击次数 |
| --- | --- |
| 50% | 6 |
| 75% | 12 |
| 90% | 30 |

该模型只解释减少失误对存活的收益，不作为实际伤害参数、破防减伤公式或随机格挡算法。

### 行为归纳与待核实参数

行为层可拆分为以下环节；此顺序用于理解和核对，不代替已知的客户端原始逻辑：

```text
装备能力与输入配置
→ 鼠标选向、左右键按下／保持／松开
→ 角色当前状态与动作切换条件
→ 攻击准备、挥击、持续格挡或挡反有效阶段
→ 防御武器与身体的接触判定
→ 确定本次攻击方向、蓄力与特性修正后的性能
→ 普通格挡比较攻防性能，挡反比较双方攻击性能
→ 区分正常格挡、直接破格挡与身体命中
→ 正常格挡结算格挡值，直接破格挡或身体命中结算对应伤害
→ 结合护甲、目标状态与特性，分别判定动作打断、移动受限、击退和击倒
→ 状态恢复，继续防御或转入下一次攻击
```

实现核对时分别保留输入方向、角色状态、动作有效阶段、接触信息、性能结算和格挡值，不用单一“正在格挡”或“破防”标志替代全部条件。正常格挡后的短硬直、格挡值耗尽后的长硬直和身体受击反应分别记录。玩法行为与当前实现不一致时，先核对客户端明确的原始逻辑，不以本文推导覆盖现有协议或动作定义。

仍需原服证据的内容包括输入采样／死区、原始挡反帧与全部方向支持、精确重量、护甲分类、性能破防系数、格挡消耗公式及各类硬直时长。当前服务端已使用上表明确标注的项目值，不再以“待核实”为由省略这些近战分支。

远程距离衰减、技能 F／E、喝药增益、未支持武将的特性以及地面“不稳定”的原始证据仍留待相应功能接入；不以近战经验参数冒充这些系统的实现。
