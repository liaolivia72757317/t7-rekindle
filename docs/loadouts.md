# 先锋阵容与武器配置

当前产品逻辑由 `src/BattleRust` 实现。下文 Python 源码链接为 `tests/reference` 中的行为对照，供数值核对和测试使用，不随产品分发。

## 使用

1. 重新构建并重启 Runtime、客户端。进入“武将 → PVP”，四个阵容槽位均可使用。
2. “更换”列表提供客户端解锁表中启用的先锋武将；教程、NPC 和测试角色不加入列表。
3. 在武将装备页配置最多四个武器槽。范围为该武将资源组内的近战武器和盾牌，不含投掷物、烟雾、药品、技能书及饰品。
4. 战场页面展示同一阵容。匹配时冻结本局阵容和每位武将的装备，首次出战及死亡后重选均使用该快照；之后的大厅编辑从下一局生效。

数字槽位键切换已配置的近战武器。盾牌槽采用本项目规则：自动切到“单手武器＋盾牌”，优先保持当前单手武器；徒手时优先恢复上次主武器（需为单手），否则选择本局装备中槽位最靠前的单手武器。已经持有该组合时只确认，不重复播放换武器动作；未装备单手武器时静默忽略请求，保持原装备，不发送提示或播放换武器动作。

空手键在徒手与上次使用的主武器间切换。盾牌随单手武器自动装备，双手武器及徒手不同时持盾。复活恢复所选武将配置中的首个近战武器；未配置近战武器时使用徒手。空阵容允许保存，但不进入匹配。

## 保存与恢复

配置保存在运行时可写目录的 `player-profile.json`，默认目录为 `%LOCALAPPDATA%\T7-Rekindle`，与启动器设置分开。通过游戏内界面编辑即可，无需修改客户端归档。

JSON 的 `schemaVersion` 为 `1`：

- `revision`：有效编辑后递增。
- `formation`：按槽位顺序排列的武将资源 ID，最多四个且不重复。
- `weapons`：以武将资源 ID 字符串为键，记录 `{slot, group, index}` 列表。`slot` 为 `1..4`；本地 `group/index` 为客户端原生 `8×6` 武器数组的零基索引。协议层将 `group` 转换为武器组资源 ID，`index` 仍为零基索引；二者均不是武器资源 ID。

仅接受该武将拥有的有效武器引用、唯一槽位与武器，最多一面盾牌。保存采用同目录临时文件和原子替换，上一份有效配置写入 `.bak`。写入失败时不提交大厅修改，并返回失败应答；主文件损坏时尝试备份，两者均无效则保留文件并报告错误。

## 战斗配置

战斗参数保存在服务端静态表 [combat_profile_data.py](../tests/reference/Business/scripts/combat_profile_data.py)，覆盖 36 名先锋、119 种近战武器／盾牌，以及包含徒手的 246 个非盾武将／武器组合。启动、选将、换武器和复活直接使用该表，不再读取客户端动作表或动画文件。[地图、出生／复活参考点及导航](computer-player.md#导航资源配置)同样由服务端静态维护。先锋目录和电脑名称仍走各自的客户端资源读取流程。

静态表按武将性别、武器类别及实际角色绑定生成，有限时长动作优先使用动画裁剪后的有效时长，并考虑播放倍率；缺少明确绑定、循环动画或分支时长不唯一时使用配置表兜底。`timingSources` 保留每个动作的表时长、动画时长和兜底原因。四向攻击的准备／出招／收招、被招架、地形反弹、换武器及冲刺均已核对。受击状态 `35` 的方向分支时长不唯一，当前使用表值 `550 ms`，同步报文与恢复定时器一致。

冲刺参数与原始伤害 ID 按 `s_battle_param_cli` 的 `(6, 0, 武器类别, 13, 2)` 选取，与客户端冲刺状态 `438/439/440/443` 的动作类型 `13` 一致，不使用动作类型 `32` 的战技参数。当前覆盖全部 210 个持近战武器的武将／武器组合；徒手和盾牌不启用冲刺。潘凤的精钢长刀、乌铁长刀使用类别 `119`：过程 `1233 ms`、位移 `1133 ms`、速度 `3500`（千分之一单位）、命中窗口 `383–783 ms`。

业务层保存本局配置，并为动作和接触保留武器快照。原生只读参数表按当前 `GePlayer` 武将 ID 和 `GeBattleState` 武器 ID 查找移动动画、突进位移时长及速度；未知组合保留原生动画，不沿用上一组合的突进参数。

普通攻击资源中的 `0/0` 接触窗口沿用“完整过程阶段可命中”规则。显式碰撞结束时间超出动画时长时，截到动画结束，并在 `windowAdjustments` 中记录原值与新值；不缩放位移速度。四向招架准备与基础成功反馈保持 `0 ms`；性能高一级的格挡成功反馈至少 `250 ms`，攻击蓄势及盾牌保持仍按住维持；不新增防御收回阶段。死亡、复活等待和跳跃／落地的原有流程不变。

静态表更新后须重新构建并重启 Runtime 和客户端，使业务与原生参数一致；热更新不替换正在进行的回合和动作快照。日常运行不执行导出脚本。需要核对新资源时，手动生成新文件、审阅差异后再更新静态表：

```powershell
python -B scripts/export_combat_profiles.py --client-directory "CLIENT_BIN" --output "combat_profile_data.generated.py"
```

`CLIENT_BIN` 使用所选客户端的绝对 `Bin` 路径。导出只读客户端资源，输出文件必须尚不存在；内容不包含本机路径或动画二进制。

## 近战伤害

[damage_data.py](../tests/reference/Business/scripts/damage_data.py)保存同一范围内的零强化武器砍／刺／钝伤、独立攻防性能字母、盾牌耐久、武将护甲、原始动作伤害 ID 及特性绑定。来源为客户端 `s_weapon_cli`、`s_weapon_attr`、`s_heroscard_cli`、`s_hero_attr`、`s_battle_param_cli`；运行时不读表。不实现远程、坐骑、等级、品质、符文及强化成长。

以下是本项目服务端规则，不作为原服公式还原结论。动作伤害 ID 到伤害类型的原始映射尚未核实：下方向优先刺伤、其次钝伤与砍伤；其余方向及冲刺优先砍伤、其次钝伤与刺伤，只选择原属性中正值。徒手采用项目基础钝伤 `20`。原始蓄势红闪时刻尚未核实，使用项目峰值 `600 ms`。配置分别标记 `baseSource`、`typeSource`、`peakSource`，不把这些默认值标为原始数据。

有效未格挡命中的伤害为各项乘积，最后按 `floor(value + 0.5)` 取整，至少 1 点；实际扣血不超过剩余生命。未命中、被格挡及穿透次数耗尽为 0。玩家与电脑的初始生命及复活生命取所选武将的原始 `max_hp`，允许自然一击致死；普通攻击和冲刺不再使用固定 `20/40` 分支。

生命上限沿 `s_heroscard_cli` 的基础属性 ID（行偏移 `0x1069`）读取 `s_hero_attr.max_hp`（420 字节行中的 `0x2c`，int32），与客户端属性 getter 一致。例如关索为 `99`、赵云为 `110`。该值离线导出为 `maxHealth`，随冻结战斗资源加载；出战、重选武将、复活和视野重建使用同一上限，逆境特性与 AI 低血量判断按各自生命百分比计算，不附加等级、品质等成长。

| 因子 | 规则 |
| --- | --- |
| 基础伤害 | 当前武器与攻击方向选中的零强化原始属性；徒手使用上述项目值 |
| 护甲 | `100 / (100 + armor × K)`；砍／刺／钝的 `K = 1 / 0.6 / 0.35` |
| 部位 | 头 `1.5`、躯干 `1`、腿 `0.75`；按原生骨骼刚体名称识别，未知按躯干并记录诊断，不按接触高度猜测 |
| 蓄势 | 从进入 Hold 计时、松键冻结；`0 ms → 1`、`600 ms → 1.5`、`1000 ms → 1.1`，线性插值后维持尾值；提前松键及冲刺为 0 ms |
| 挥击阶段 | 有效窗口归一化后 `(0, .25) → (.35, 1) → (.65, 1) → (1, .25)` |
| 相对速度 | 基准向量为接触点武器速度减攻击者平移速度；相对角色速度沿基准的投影除基准速率后加 1，限制到 `0.5..1.5`；基准低于 `0.1 m/s` 或采样不连续时为 1 |
| 友军衰减 | 友军不扣血且同一 RID 仅计一次；此前擦过 0／1／至少 2 名友军时为 `1 / .4 / .05`；衰减命中显示黄色伤害、攻击性能降为 F；不打断重甲的攻防，轻／中甲仍可打断 |
| 敌人穿透 | 无 `[1]`、低 `[1,.5]`、中 `[1,.65,.4]`、高 `[1,.8,.6,.4]`；取武器绑定的顺劈等级，超过长度停止扣血 |

仅应用武将或武器实际绑定的特性：反制在长柄下方向命中正在 Strike 的目标时伤害 `×1.2`、攻击性能 `+1`，不含 Prepare／Hold；轻盈在攻击者腾空时 `×1.15`；蓄力精通将蓄势超出 1 的部分 `×1.25`；逆境在生命不高于 30% 时 `×1.2`；背后 120° 锥内的刺客低／中／高分别 `×1.1/1.2/1.3`。反击、连击分别由成功格挡、有效命中触发 `×1.2` 持续 3 秒，狂怒由击杀触发 `×1.2` 持续 5 秒。触发增益从后续攻击生效，同名刷新不叠层，不同增益相乘；持续时间按接触发生时刻判断。未实现的原始绑定仅保存 ID，不默认激活。

盾牌成功挡住攻击后扣自身原始耐久，不受护甲和部位倍率影响，其他适用倍率照常，破盾特性另 `×1.5`。打碎盾牌的一击仍全部吸收、不溢出扣血；播放原有破盾状态 `41`（1000 ms），本条生命内禁用副手，换武器不修复，复活或重新出战恢复耐久。攻击性能直接击破防御时改按减伤身体命中结算，不与耗尽耐久的破盾混为同一条路径。

进入 Strike 时冻结武器、基础属性、攻击性能、相对重量、伤害类型、已松键蓄势、特性及规则；接触记录保留防御武器 ID、刚体索引、双方平移速度、武器接触点速度和双方独立的腾空标记。延迟投递不改用当前武器、当前帧速度或投递时间。纯计算入口见 [damage_rules.py](../tests/reference/Business/scripts/damage_rules.py)，结算与快照见 [damage_state.py](../tests/reference/Business/scripts/damage_state.py)。

## 格挡、挡反与受击参数

性能字母由 `s_weapon_attr` 原始显示字段分别导出，不能从伤害或盾牌耐久反推；空白性能按项目 F 处理。势大力沉仅在武器实际绑定且 Hold 满 `600 ms` 时修正性能；普通格挡比较攻防性能，挡反比较双方攻击性能，B 级不设例外。

格挡值 `5`、恢复等待 `2500 ms`、每秒恢复 `2`、主动命中／被挡恢复 `2`、耗尽重置 `2` 使用 `s_battle_common_para_cli` 原始参数 `91/93/94/95/97`。消耗公式、破防减伤、挡反窗口、硬直与击倒时间采用已确认的项目经验值，集中在 [guard_rules.py](../tests/reference/Business/scripts/guard_rules.py)。原始重量显示缺少可用值，暂按绑定移动重量分类赋相对权重；护甲类型暂按数值护甲映射，均在 `damage_resources.py` 标记项目来源。完整参数与判定顺序见[格挡与受击参数来源](combat-rules.md#格挡与受击参数来源)。

业务状态版本为 `19`，原生接触证据版本为 `2`。旧版本已初始化或已进入战斗的实例拒绝热迁移，保留旧 revision 与状态；大厅和未初始化实例可迁移。升级需重新构建并重启 Runtime 和客户端。离线属性导出：

```powershell
python -B scripts/export_damage_profiles.py "CLIENT_BIN" "damage_data.generated.py"
```

## 定向验证

- Python：`test_hero_resources.py`、`test_player_profile.py`、`test_combat_resources.py`、`test_loadouts.py`；`test_animation_timing.py`、`test_combat_export.py` 验证动画选择和窗口截断，`test_static_action_clocks.py` 遍历全部组合，核对报文、计时器及防御零时长。
- Native：`T7R.RuntimeTests.exe --combat-profiles` 验证实际执行的 x86 参数选择；`--resource-preflight PACKAGE_ROOT` 验证资源预检与启动传递，`PACKAGE_ROOT` 使用构建脚本生成的合成测试包。
- 伤害：`test_damage_rules.py`、`test_damage_resources.py`、`test_damage_integration.py` 验证公式、完整配置覆盖、蓄势快照、延迟接触、友军／顺劈、增益及盾牌；`T7R.RuntimeTests.exe --frame-hooks` 验证原生部位与事件速度采集，`--server-context PACKAGE_ROOT` 验证跨语言证据传递。
- 界面验收：配置四名不同先锋 → 为两名武将配置不同武器 → 检查战场阵容 → 分别首次出战与复活重选 → 核对模型、武器、切换、攻击、持盾和突进 → 重启后核对保存结果。
