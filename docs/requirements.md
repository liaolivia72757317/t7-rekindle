# 产品需求与使用说明

## 当前范围

铁骑·重燃通过 Windows x64 启动器为原版《刀锋铁骑》客户端提供本地服务。当前已有启动器、登录与场景消息、基础移动和战斗状态初始化等实现，尚未完成完整人机对战或局域网联机。

目标是先完成一张地图、固定模式下可重复的人机对战，再扩展局域网多人游戏。阶段验收见[实施计划](planning/implementation-plan.md)，具体待办见[任务清单](planning/task-list.md)。

## 运行环境与程序包

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 22H2（build 19045）或 Windows 11，x64 |
| 托管运行时 | .NET Framework 4.8 或兼容的更高版本；仅运行程序不需要 Developer Pack |
| 图形能力 | 预检要求 Direct3D 9 硬件设备支持 Pixel Shader 3.0 和 Vertex Shader 3.0 |
| 游戏客户端 | 自行准备与下述基线匹配的原版 x86 客户端及完整资源 |
| 启动器文件 | 完整产品目录；包含原生 DLL、托管依赖、嵌入式 Python 和业务脚本 |

.NET Framework 运行时可从 [Microsoft 下载页](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48)获取。完整产品包自带 Python；仅运行启动器不需要安装 Python、Visual Studio 或 .NET SDK。

项目尚未正式发布。从源码制作程序包见[开发与交付](development.md)；使用 CI 产物时，应先查看对应提交的测试结果和已知限制。

- **安装器**：运行 `T7-Rekindle-Setup.exe`。默认安装到当前用户的 `%LOCALAPPDATA%/Programs/T7-Rekindle`，可修改目录；桌面快捷方式按需勾选。
- **便携包**：完整解压 `T7-Rekindle-windows-x64.zip` 后运行包根目录的 `T7-Rekindle.exe`。不要只复制 EXE，也不要把启动器文件混入游戏客户端目录。

## 客户端兼容性

典型游戏根目录结构如下：

```text
游戏根目录/
  Bin/
    TieJiClient.exe
    ProtocalHandler.dll
  Data/
  vfs/
```

目录结构正确不等于版本兼容。当前预检按以下两个文件的 SHA-256 识别支持的基线，文件名中的 `Protocal` 与客户端实际名称一致：

| 文件 | SHA-256 |
| --- | --- |
| `Bin/TieJiClient.exe` | `3c205c7efaf1956bc2c458b1073e5273a9fef29e3e5ee18418f93f418eeaa5c8` |
| `Bin/ProtocalHandler.dll` | `432ea9dd64d7b90af5fed323e52ce33d0a035a3b13cf4ac75a050f0611776d18` |

可在 PowerShell 中只读检查文件：

```powershell
$clientRoot = Read-Host '请输入游戏根目录的完整路径'
Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $clientRoot 'Bin/TieJiClient.exe')
Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $clientRoot 'Bin/ProtocalHandler.dll')
```

比较时忽略哈希字母大小写。基线定义位于 [Bootstrap.cpp](../src/Runtime/launcher/Bootstrap.cpp)；运行时还会检查入口签名。哈希不匹配时停止启动，不通过替换零散 DLL 或修改文件来拼凑版本。基线匹配也不代表完整玩法已经通过验收。

## 使用启动器

1. 打开“游戏设置”，通过“浏览…”选择游戏根目录。已有的客户端程序目录也受支持；选择上级目录时，按最近层级优先、同层目录名排序查找第一个有效客户端，并回填路径。
2. 点击“重新检查”验证客户端基线和图形能力。目录变化时的结构检查在后台执行；重新浏览、修改路径或关闭窗口会取消旧扫描。
3. 在“启动”页填写玩家名称。名称去除首尾空白后按 GBK 编码计算，最多 31 字节；不接受控制字符、emoji 或其他 GBK 不支持的字符。
4. 目录与名称验证通过后自动保存。点击“启动游戏”会再次预检，再准备本地服务并启动客户端。
5. 启动早期可取消；进入创建客户端阶段后隐藏取消入口。运行时可确认“结束游戏”；关闭启动器也会确认并结束活动会话。建议先从游戏内正常退出。

“游戏进程运行中”仅表示客户端进程正在运行，不表示已经登录、进图或可以完成对战。客户端退出码 `0` 和 `4660`（`0x1234`）按正常退出处理，其余退出码显示异常反馈；资源清理未完成时不允许再次启动。

## 界面与关于信息

- “启动 / 游戏设置 / 关于”共用同一会话；切换页面不会结束游戏。顶部版本信息、导航和底部主操作固定，中间内容可滚动。
- 窗口默认 800 × 600，最小 720 × 560。使用浅色默认主题，并保留深色偏好和系统高对比度支持。
- 关于页提供离线版本日志、Git 提交信息、许可证和感谢说明。缺少提交或项目地址时显示明确空态。
- “检查启动器更新”仅在点击时联网，优先使用 R2 镜像，失败时查询当前仓库的 GitHub Releases 最新正式版本，显示版本比较与发行说明。用户点击下载安装版后，弹窗展示进度并支持取消；完整性校验通过后，再点击“立即安装”，按现有退出流程确认并清理会话后启动安装向导。不查询预发布版或 CI 开发构建。旧发布缺少校验信息时保留手动发布页入口。
- 无正式版本时显示“暂无正式发布版本”；本地版本较新时不提示降级。网络失败、超时、请求受限或版本信息异常会明确提示，不影响本地启动。
- 游戏内感谢名单、角色与进度存档仍是规划项，启动器的设置保存不等于保存游戏进度。

## 设置与诊断资料

安装版和便携版均使用当前 Windows 用户的 `%LOCALAPPDATA%/T7-Rekindle`，而不是把用户数据写入程序目录：

| 相对路径 | 内容 |
| --- | --- |
| `settings.json`、`settings.json.bak` | 客户端目录、玩家名称、窗口尺寸和主题偏好，以及设置备份 |
| `logs/desktop.log` | 启动器界面和托管服务日志 |
| `logs/native.log` | 原生运行时诊断 |
| `data/` | 会话 Journal 和业务脚本 revision 记录，不是游戏存档 |

启动页的“打开日志目录”可用于定位诊断文件。诊断资料不自动上传；卸载启动器不会删除这些用户数据，也不会删除游戏客户端。设置格式和日志保留规则见[运行契约](runtime-contracts.md)。

## 问题排查与反馈

| 现象 | 检查方法 |
| --- | --- |
| 目录无效或自动找到了另一份客户端 | 选择更精确的游戏根目录，确认 `Bin` 内两个程序文件和根目录下 `Data`、`vfs` 齐全 |
| `unsupported client/protocol baseline` | 按上面的命令核对两个文件的 SHA-256；反馈哈希结果，不上传客户端文件 |
| `host D3D9 unavailable` 或 `host D3D9 capability gate failed` | 检查图形驱动和运行环境是否提供表中要求的 D3D9 硬件能力 |
| 玩家名称无效 | 缩短名称，移除控制字符及 GBK 不支持的字符；31 字节不等于 31 个汉字 |
| 原生 DLL 加载失败 | 确认使用完整 x64 产品包及 .NET Framework 运行时，没有混用不同构建的文件 |
| 启动失败、异常退出或清理未完成 | 记录界面错误、退出码和操作步骤，并查看两份日志 |
| 进程运行但游戏流程不完整 | 对照[当前状态](../README.md#当前状态)与[待办](planning/task-list.md)，区分已知未完成功能和回归问题 |

向本仓库 Issue 提交启动器版本或提交号、包的来源、Windows 版本、客户端基线检查结果、复现步骤、预期与实际表现，并注明是否启动真实客户端。截图和日志只保留相关片段，去除用户名、个人路径、账号及票据等信息。敏感安全问题见[安全说明](../SECURITY.md)。
